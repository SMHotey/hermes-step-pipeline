# AGENTS.md — hermes-step-pipeline

Плагин Hermes: конвейер шагов «план → постановка → исполнение → ревью → журнал».
Репозиторий общий, продукта внутри нет: ни имён проектов, ни бизнес-логики.

## Границы

- `step_pipeline/engine/` — единственный источник движка. Копии в проектах
  (`.pipeline/`) не правятся руками: их обновляет `hermes pipeline setup --upgrade`.
- `step_pipeline/roles/` — универсальные роли. Проектные роли и их предметные скиллы
  живут в проекте, не здесь.
- Всё проектное — в `pipeline.json` проекта, не в коде плагина.

## Проверки перед коммитом

```bash
python -m pytest -q                       # 93 теста: плагин + движок
hermes plugins validate step_pipeline     # манифест, tools, security-скан
```

Ломающее изменение движка или формата `pipeline.json` — минимум минор версии и
запись в `CHANGELOG.md`.

## Конвенции

- Комментарии, docstring'и, сообщения пользователю, коммиты — по-русски.
- Зависимости — только stdlib и Hermes; никаких внешних пакетов ради удобства.
- Секреты — только в `.env` профиля; в коде и логах их быть не может (проверка
  маскирует токен в выводе).
- UI слушает только localhost; действия в режиме предпросмотра запрещены.
- CI гоняет тесты на ubuntu и windows; `hermes`-валидация выполняется, если CLI есть.

## Структура

```
step_pipeline/   пакет плагина (манифест, CLI, UI, движок, роли, шаблоны)
tests/           тесты плагина; tests/engine/ — тесты движка как отдельного слоя
```
