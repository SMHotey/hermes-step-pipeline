## План и шаги

- Источник правды — `<plans_dir>/<НОМЕР>-<слаг>.md`: раздел шагов и журнал выполнения.
  Шаг определяется по журналу, а не по памяти сессии.
- Контекст шага: `python .pipeline/next_step.py` (машинный формат — `--json`).
- **Шаг не начинается с кода.** Сначала постановка роли `prompter`
  (`<prompts_dir>/<дата>_<план>-<шаг>_prompt.md`, гейт
  `python .pipeline/check_task_prompt.py <файл>` = PASS), затем исполнение, затем
  ревью роли `reviewer`.
- **Исполнитель шаг не закрывает.** Строку «ЗАКРЫТ» в журнале и коммит закрытия
  делает страж (`gate.py`) только после вердикта APPROVE.
- Вердикт ревьюера — файл `<reviews_dir>/<план>-<шаг>.md` с РОВНО ОДНОЙ строкой
  `## ВЕРДИКТ: APPROVE` или `## ВЕРДИКТ: REQUEST_CHANGES` и ссылкой на коммит.
- **Режим планировщика** включён по умолчанию: проверить — `hermes pipeline plan-mode
  status`, выключить — `hermes pipeline plan-mode off` (действует сразу).
- Фразы «составь план», «спланируй», «план работ» — запрос на планирование: загрузить
  скилл `pipeline-plan-authoring` и работать по его протоколу.
- План пишется черновиком в подкаталог `drafts/` каталога планов. Утверждает и переносит
  владелец — `hermes pipeline plan --accept`; агент этого не делает.

## Конвейер

- Страж: `python .pipeline/gate.py --status` (что видно), `--run` (один тик),
  `--plans` (таблица планов). Cron: каждые 10 минут, `--no-agent`, `--deliver local`.
- Стоп-фраза владельца: «остановка после выполнения шага» в любой сессии =
  `python .pipeline/gate.py --stop "<фраза>"`. «Продолжай» = `--resume`.
- Ручной допуск шага: `--hold <ШАГ>` / `--unhold <ШАГ>` (миграции, деплой, внешние
  сервисы). Без `--plan` команды пишут в состояние плана по умолчанию.

## Коммиты

- Коммит после каждого шага: `git add <файлы шага>`, НЕ `git add -A` (в дереве бывают
  правки параллельной сессии). Сообщение на русском, по существу шага, затем `git push`.
- Страж коммитит только файл плана и файл отчёта ревью.

## Тесты

- Тесты — контракт: существующие не удалять и не ослаблять.
- Точечный прогон по умолчанию (гейты шага). Полный набор — перед коммитом крупных
  изменений, перед релизом или по прямому требованию.
- Один тяжёлый прогон за раз: параллельные прогоны дают ложные падения.
