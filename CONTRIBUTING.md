# Как участвовать

Плагин небольшой и держится на трёх правилах: движок детерминирован, проектное — в
`pipeline.json`, ничего лишнего в зависимостях.

## Быстрый старт

```bash
python -m venv .venv
.venv/Scripts/python.exe -m pip install pytest        # Windows
# .venv/bin/python -m pip install pytest              # Linux/macOS

.venv/Scripts/python.exe -m pytest        # 600+ тестов, ~7 минут
hermes plugins validate step_pipeline     # манифест, инструменты, security-скан
```

`pytest.ini` уже включает `-q`: второй `-q` скрывает итог прогона.

## Что куда

| Каталог | Что там |
|---|---|
| `step_pipeline/engine/` | движок, который копируется в проект (`.pipeline/`): страж, парсеры, роли-скрипты |
| `step_pipeline/roles/` | универсальные скиллы ролей (копируются в `.hermes/skills/` проекта) |
| `step_pipeline/ui/` | панель: один `index.html` без сборки |
| `step_pipeline/*.py` | плагин: CLI, мастер установки, Telegram, снимок, обновление |
| `tests/` | тесты плагина; `tests/engine/` — тесты движка отдельным слоем |
| `docs/` | контекст, формат плана, планы разработки, ревью |

Правила формата плана — нормативный `docs/PLAN-FORMAT.md`; менять формат без него нельзя.

## Границы

- **Движок правится только здесь**, в `step_pipeline/engine/`. В проектах `.pipeline/` —
  вендоренная копия, её обновляет `hermes pipeline setup --upgrade`. Правка копии в
  проекте вернётся при первом обновлении.
- **Проектное — в `pipeline.json` проекта**, не в коде плагина.
- **`driven_plans` и `profiles` в `pipeline.json` меняет только владелец.** Шаг конвейера
  их не трогает.
- **Имена и бизнес-логика проектов-потребителей в репозиторий не попадают.** Ни в коде,
  ни в документации, ни на скриншотах: только демо-проект.

## Стиль

- Комментарии, docstring'и, сообщения и коммиты — по-русски.
- Зависимости — только stdlib и Hermes. Внешние пакеты не добавляем: плагин должен
  ставиться без `pip`.
- Тест обязателен на то, что ломалось: если баг был — сначала тест, потом правка.
- Комментарий объясняет **почему**, а не что: «почему так, а не иначе» — то, что теряется.

## Изменение движка или формата

1. Правка в `step_pipeline/engine/` (или `docs/PLAN-FORMAT.md`).
2. `pytest` целиком — зелёный.
3. Минимум минор версии в `step_pipeline/plugin.yaml` и запись в `CHANGELOG.md`.
4. В проектах — `hermes pipeline setup --upgrade` (упомянуть в PR).

## Новая роль

1. `step_pipeline/roles/<имя>/SKILL.md`.
2. Строка в `SKILL_CATEGORIES` (`setup_flow.py`) — в какую категорию `.hermes/skills/`
   она попадает.
3. Упоминание в `templates/pipeline.json.example` (роль и лимиты).

## Pull request

- Заголовок — как коммит: `feat(engine): ...`, `fix(ui): ...`, `docs(...): ...`.
- В описании: что меняется, почему, как проверено (команды и вывод), чем рискуем.
- CI должен быть зелёным: `pytest` на ubuntu+windows, py3.11/3.13, `plugins validate`.
- Ломающее изменение поведения движка или формата `pipeline.json` — минимум минор версии,
  запись в `CHANGELOG.md` и предупреждение в описании PR.
