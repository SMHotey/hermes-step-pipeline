# Changelog

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — semver.
Ломающее изменение поведения движка или формата `pipeline.json` — минимум минор.

## [0.4.0] — 2026-11-02

Одно имя плагина, порт UI в конфиге проекта, лицензия и гигиена репозитория.

### Изменено

- Имя плагина в манифесте — `step_pipeline` (было `step-pipeline`): совпадает с
  каталогом, Python-пакетом и `toolset` из `__init__.py`.
- Порт UI живёт в `pipeline.json` проекта: ключ `ui_port`, значение по умолчанию 8770
  добавлено в `templates/pipeline.json.example`; флаг `--port` перекрывает конфиг.
- Из `config_schema` манифеста удалены мёртвые ключи `project_root` и `ui_port`:
  их не читал ни один модуль плагина.
- README: одно имя во всех командах, раздел про порт UI, раздел «Лицензия».

### Добавлено

- `LICENSE` (MIT) и упоминание в README.
- Записи `.gitignore`: `.pipeline/`, `.hermes/`, `docs/templates/`, `.idea/` —
  артефакты установки и IDE больше не висят в `git status`.
- Тесты `tests/test_manifest_hygiene.py` (имя манифеста совпадает с каталогом, нет
  мёртвых ключей, лицензия на месте, `.gitignore` закрывает артефакты, README без
  старого имени) и `tests/test_cli_ui_port.py` (порт из конфига проекта и перекрытие
  флагом).

### Почему

- Два имени жили одновременно: `plugins update` и `plugins remove` резолвят каталог
  `plugins/step_pipeline`, а `plugins list` и `plugins show` печатают имя из манифеста,
  поэтому половина команд README не выполнялась. Смена имени в манифесте — минор,
  потому что установленные копии с прежним `plugins.enabled` требуют одного
  `hermes plugins enable step_pipeline`.

## [0.3.0] — 2026-11-02

Тик не запускается на разъехавшейся копии движка.

### Добавлено

- Маркер целостности `.pipeline/ENGINE.sha256` — sha256 по содержимому всех `.py`
  движка; пишется при `setup` и `setup --upgrade`.
- Проверка перед тиком: `gate.py --run` сверяет движок с маркером и при расхождении
  не выполняется (код 3, в stderr — команда обновления). Легаси-установки без маркера
  продолжают работать.
- Тесты `tests/engine/test_engine_integrity.py`: стабильность хеша, дрейф, пустой
  маркер, легаси, согласованность `setup_flow` и движка.

### Почему

- Прецедент 02.11.2026: в проекте работала копия `gate.py` (1364 строки), в плагине
  лежала другая (1599 строк) — обе с `VERSION 0.2.0`. План двигали две разные логики:
  один конвейер шёл по шагам, которые считал следующими по своей версии разбора.

## [0.2.0] — 2026-11-01

Конвейер отвечает в чате и перестал молчать под cron.

### Добавлено

- Приём команд владельца из Telegram: `gate.py --commands` — один `getUpdates` с offset
  в `.pipeline/state/tg_offset.json`. Команды `/status`, `/plans`, `/stop [причина]`,
  `/resume`, `/hold ШАГ`, `/unhold ШАГ`, `/help`. Отвечаем только в настроенный чат,
  чужие сообщения игнорируем, на вебхуке (409) сообщаем причину, а не молчим.
- `setup` заводит вторую cron-джобу «бот команды» раз в минуту (no-agent) и кладёт
  `profiles/<профиль>/scripts/pipeline_commands.py`: страж идёт раз в 10 минут,
  а `/status` и `/stop` столько ждать нельзя.
- Ключ `notify.commands` в `pipeline.json` (включён по умолчанию там, где включены
  уведомления).

### Исправлено

- Тик-скрипт сам читает `.env` профиля: cron шлюза отдаёт `HERMES_HOME`, но не переменные,
  поэтому уведомления движка молчали (в stderr уходило только `[notify] нет токена/чата`).
- Установленный тик-скрипт получил UTF-8 в stdio и поиск `gate.py` по четырём местам:
  раньше это была урезанная копия без того и другого.
- `setup` делает `skills trust` всем трём ролям, а не только исполнителю: иначе воркеры
  постановщика и ревьюера падали `Unknown skill(s)` и карточка уходила в `blocked`.

### Тесты

- 126 тестов; новые: `tests/engine/test_tg_commands.py` (15), `tests/engine/test_tick.py` (7).

## [0.1.0] — 2026-11-01

Первая рабочая версия: конвейер шагов как плагин Hermes.

### Добавлено

- CLI `hermes pipeline setup|status|run|ui|doctor|notify-test|config`.
- Движок конвейера в `<проект>/.pipeline/`: реестр планов по файлам, контракт шага из
  плана, страж «шаг → постановка → исполнение → ревью → журнал → следующий шаг»,
  идемпотентные карточки канбана, инцидентные и владельческие стоп-флаги, ручной допуск.
- Роли-скиллы: orchestrator, prompter, reviewer, next-step, plan-authoring,
  agent-prompt-authoring.
- Локальный UI (stdlib, без сборки): поток шага, планы, шаги, карточки, журнал,
  кнопки тик/стоп/продолжить, настройки, самопроверка Telegram.
- Фоновый запуск UI: `--detach` (PID в `.pipeline/ui.json`), `--stop`.
- Предпросмотр без установки: `--preview` читает настоящие планы и карточки проекта
  движком плагина, ничего не записывая; действия выключены.
- Мастер установки спрашивает токен бота (скрытый ввод, проверка `getMe`), находит
  chat id через `getUpdates`, шлёт тестовое сообщение; уведомления через Bot API.
- Создание борды, профилей ролей (clone + `reasoning_effort=max`), лимитов канбана,
  cron-джобы стража, `.gitignore`.
- Маркер `.pipeline/VERSION` и `setup --upgrade`: обновление движка в проекте без
  переустановки плагина и без потери конфига.
- Инструменты агента: `pipeline_status`, `pipeline_run`, `pipeline_control`.
- Тесты: 48 плагина + 48 движка (e2e с поддельным `hermes`, фейковый Bot API, UI, предпросмотр).
