## 4. Что сделать

### 4.1 `step_pipeline/stats.py` — новый файл, только stdlib

Модуль не импортирует движок (`docs/CONTEXT.md:44`) и ничего не пишет на диск: только
читает файлы проекта. Ни одна функция не бросает исключений наружу — нечитаемый файл
попадает строкой в `errors`, а его числа считаются нулём.

Публичный API — три функции и константы разбора:

```python
RESEARCH_MARKER = "разведка"
EDIT_MARK_RE = re.compile(r"прав\w*\s+по\s+разведке\s*:\s*(\d+)", re.IGNORECASE)
VERDICT_RE = re.compile(r"^#{0,4}\s*ВЕРДИКТ\s*:\s*(APPROVE|REQUEST_CHANGES)\s*$",
                        re.IGNORECASE | re.MULTILINE)
PLAN_SHA_RE = re.compile(r"plan_sha256\s*[:=]\s*`?([0-9a-f]{64})", re.IGNORECASE)
PLAN_FILE_RE = re.compile(r"^(\d{1,2})-")       # номер плана — группа 1
STEP_HEADING_RE = re.compile(r"^#{3,}\s+[A-Za-z]{1,4}\d+[A-Za-z]?(?:-\d+)?\b")

def cycle_metrics(root, cfg=None) -> dict      # все числа; root — Path проекта
def cycle_tiles(metrics) -> list[dict]         # четыре плитки для панели
def render_cycle(metrics) -> str               # одна строка «Цикл: …» для --status
```

`cfg` — сырой словарь `pipeline.json` (как `proj.read_config`: словари `paths` и
`markers`); `None` — умолчания. Читаются ключи `paths.plans` (`docs/plans`),
`paths.reviews` (`docs/reviews`), `paths.research` (`docs/research`, ключа в проекте
нет — умолчание), `paths.state` (`.pipeline/state`), `markers.journal` (`журнал`).

Правила счёта — R1-R9. Каждое правило в докстринге модуля со ссылкой на источник в
движке (§2.1): при правке движка расхождение должно находиться по ссылке.

R1. План — файл вида `NN-имя.md` в каталоге планов (`PLAN_FILE_RE`), в тексте которого
есть заголовок уровня 2 с маркером журнала — как `registry.discover`
(`engine/registry.py:229-245`). `plans_total` — число таких файлов.

R2. Разведка в плане — заголовок уровня 2-6, в тексте которого есть «разведка» без
регистра, который не является заголовком шага (`STEP_HEADING_RE` по восстановленной
строке) и не лежит внутри раздела шагов (уровень выше 2 при последнем заголовке
уровня 2 со словом «шаг» не считается) — дословно правило `plan_cycle.research_section`
(`engine/plan_cycle.py:73-107`).

R3. Артефакт плана — файл `N-prior-art.md` в каталоге разведки, где N — номер плана
(`engine/gate.py:536`). `plans_with_research` — планы, у которых есть И R2, И артефакт.
План с R2 без артефакта попадает в `research_gap` (список номеров).

R4. Вердикты — только по разделу артефакта, в заголовке которого есть «кандидат»
(разбор разделов — как `scout_report.split_sections`: заголовки `## `); нет такого
раздела — считать нечего, в `errors` строка «нет раздела «Кандидаты»». Строки таблицы —
строки, начинающиеся с `|`; первая строка таблицы — шапка, строка-разделитель
(все ячейки из дефисов) пропускается. Вердикт — последняя ячейка строки (это работает
и на восьми колонках шаблона, и на пяти колонках старого артефакта).
Классификация ячейки без учёта регистра, в этом порядке:
- `candidates_own`: есть «своё» ИЛИ есть «не берём» (отрицание проверяется ДО «берём»);
- `candidates_with_solution`: есть «берём» ИЛИ «форкаем»;
- `candidates_unknown`: всё остальное, включая пустую ячейку.
Вторые таблицы файла (например «Что берём и куда это ложится» в `5-prior-art.md`)
не считаются: они вне раздела «Кандидаты».

R5. Правки по разведке — `EDIT_MARK_RE` по тексту плана, только у планов с R3.
`edits_total` — сумма, `edits_plans` — сколько планов имеют отметку, `edits_per_plan` —
`round(edits_total / edits_plans, 1)` либо `None`, когда отметок нет.

R6. Ревью плана — файл `plan-N.md` в каталоге отчётов (`engine/approval.py:136`).
Вердикт — первое совпадение `VERDICT_RE` (`search`, как в движке); метка версии —
`PLAN_SHA_RE`; `sha256` файла плана — по сырым байтам (`hashlib`, как `sha256_file`
в `approval.py:70`). Состояние по плану, ровно одно:
- `missing` — файла нет;
- `invalid` — файл есть, вердикта нет;
- `pending` — `REQUEST_CHANGES`;
- `stale` — `APPROVE`, но метки нет либо метка не равна sha256 файла плана;
- `fresh` — `APPROVE` и метка равна sha256 файла плана.
Счётчики: `plan_reviews` — число `fresh`, `plan_reviews_stale` — число `stale`,
`plan_reviews_pending` — число `pending`.

R7. Круги ревью плана — строки истории `history.jsonl` (по строке на действие,
`engine/gate.py:3602`): считаются записи с `action` = `create_plan_review` и `plan`,
равным номеру плана. Битые строки JSON пропускаются и попадают в `errors` одной
строкой «история: пропущено строк N» (только если N больше нуля).
`plan_reviews_first` — планы в состоянии `fresh`, у которых ровно один круг.

R8. `errors` — список строк, порядок — порядок обхода. Пустой список означает «все файлы
прочитаны». Отсутствие каталогов планов, отчётов, разведки — не ошибка: это проект,
где механизм ещё не работал, все счётчики нули.

R9. `by_plan` — список словарей по планам, по возрастанию номера:
`{"plan": "5", "research": True, "artifact": "docs/research/5-prior-art.md",
  "candidates": 5, "own": 3, "edits": None, "review": "fresh", "rounds": 1}`.
Поле `artifact` — путь относительно корня проекта или пустая строка; `edits` — число из
отметки либо `None`; `review` — состояние из R6; `rounds` — круги из R7.

`cycle_tiles(metrics)` — ровно четыре плитки в этом порядке, формат каждой
`{"label": str, "value": str, "hint": str}`; значения уже строками, страница их только
рисует (правило «страница — рисовальщик», `snapshot.py:467-472`):

1. `планов с разведкой` — значение `«N из M»`, подсказка — номера планов с разведкой либо
   «ни одного»; если `research_gap` не пуст, к подсказке добавить «без артефакта: …».
2. `вердиктов без готового решения` — значение `«own из total»` (при нулевом total —
   прочерк), подсказка — «готовых N, своих M, нераспознанных K».
3. `правок по разведке на план` — значение из `edits_per_plan` либо прочерк, подсказка —
   «N правок в M планах» либо «отметок нет».
4. `ревью плана с первого раза` — значение `«first из plans_total»`, подсказка —
   «свежих вердиктов N, устаревших M, ждут K».

`render_cycle(metrics)` — одна строка без переводов строки:
`Цикл: планов 5, с разведкой 1, кандидатов 5 (готовых 2, без готового 3), правок по разведке —, ревью плана 0 из 5 (с первого раза 0)`.
Прочерк вместо числа правок — когда `edits_per_plan` равен `None`; иначе число.

В конце модуля — блок `if __name__ == "__main__":` (ручная проба владельца):
аргумент — путь проекта (по умолчанию текущий каталог), печать `render_cycle` после
`cycle_metrics`, код возврата 0. UTF-8 в stdout — как в движке (`errors="replace"`).

## 5. Как проверить (гейты)

## 7. Формат отчёта

До коммита, по порядку, на русском:

1. `git status --porcelain` и `git diff --stat`: какие файлы и сколько строк.
2. Ключевые диффы: константы и функции `stats.py` (правила R1-R9 и их источники),
   блок в `render_status`, три точки `snapshot.py`, секция и `renderCycle` в странице.
3. Решения, принятые самостоятельно, с причиной (D1, D2 и все отступления; спорное —
   вопрос владельцу, не догадка).
4. Строки гейтов: команда, фактическое число `passed`, `EXIT`, рядом замер шага 0.
5. Вывод гейта 6 дословно — это и есть «числа из файлов».
6. Отклонения от постановки по пунктам, с обоснованием.
7. Что сознательно не сделано (движок, старый артефакт разведки, счётчики для S9-S10) и
   версия с строкой `CHANGELOG.md`.
8. После отчёта — коммит только перечисленных в §3 файлов (явные пути, без `git add -A`),
   затем `git log -1 --format=%H` в отчёт и `git push`.

## 8. Вопросы (≤3, каждый с ценой)

1. Где живут числа: сейчас это плагин — `hermes pipeline status` и панель, а
   `gate.py --status --json` ключа `cycle` не получает. Цена второго варианта —
   правка движка внутри S8, новая синхронизация `ENGINE.sha256` и `setup --upgrade` во
   всех проектах-приёмниках. Принято: плагин, движок не трогаем. Оставляем так?
2. Старый артефакт `docs/research/5-prior-art.md` не проходит `scout_report` (5 колонок,
   нет строки «Решение:»). Принято: считать вердикты по последней ячейке и ничего не
   переписывать. Цена строгого варианта — привести артефакт к шаблону S3 руками (около
   получаса и правка чужого артефакта задним числом). Оставляем мягкий счёт?
3. Метрика «с первого раза» опирается на историю тиков: у планов, прошедших ревью до
   включения механизма, кругов в истории нет, и в число они не попадут. Принято:
   строго `rounds == 1`. Цена послабления (`rounds == 0` тоже «с первого раза») —
   число завышено и не отличает механизм от ручного ревью. Оставляем строго?

## 9. Ревью (обязательно)

Шаг не закрывает исполнитель. После зелёных гейтов — независимое ревью ролью `reviewer`
(скилл `pipeline-reviewer`) по плану `docs/plans/5-platforma.md` и по коду. Отчёт
исполнителя ревьюеру источником фактов не является: он читает план, diff и постановку
`docs/prompts/2026-11-08_5-S8_prompt.md`. Вердикт — APPROVE или REQUEST_CHANGES, ровно
одна строка вердикта в `docs/reviews/5-S8.md`, первая строка отчёта — `recon_commit:`
с полным sha коммита шага. При REQUEST_CHANGES шаг остаётся открытым: находки правятся,
ревью повторяется. Строка «ЗАКРЫТ» в журнале плана и коммит закрытия — только после
APPROVE.
