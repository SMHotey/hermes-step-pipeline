## 1. Роль и цель

Ты — разработчик плагина `hermes-step-pipeline` (Python 3.11, зависимости — только
stdlib и Hermes). Код, комментарии, коммит и отчёт — по-русски.

Цель шага: тик, который cron шлюза запускает из каталога профиля, перестаёт быть
рукописной копией движка. Установленный скрипт — ровно файл `step_pipeline/engine/tick.py`,
мастер и `upgrade` его обновляют, а не создают один раз, и он больше не умирает молча,
когда `gate.py` не найден. Канал уведомлений проверяется не командой CLI
`notify-test`, а пробой в том же пустом по переменным `STEP_PIPELINE_*` окружении,
в котором работает джоба.

Готово = выполнено всё перечисленное:

1. В `step_pipeline/setup_flow.py` больше нет рукописного литерала тика: текст берётся
   из `proj.ENGINE_SRC / "tick.py"`, а установка пишет байты этого файла — установленный
   `pipeline_tick.py` побайтово равен файлу движка (одинаковый `sha256`).
2. `ensure_cron` пишет/обновляет скрипт профиля при каждом запуске мастера, включая
   случай «джоба уже есть»; вторая джоба не создаётся.
3. `upgrade` обновляет установленный скрипт, если у проекта есть `.pipeline/cron.json`,
   и не создаёт его, если cron не заводили; итоговая строка `upgrade` больше не
   утверждает, что cron не тронут, когда скрипт обновлён.
4. Установленный скрипт при отсутствии `gate.py` печатает причину в stderr и возвращает
   код 1 (сейчас в установленной копии — молчаливый код 0).
5. `python -m pytest tests/engine/test_tick.py` → `15 passed` (10 существующих + 5 новых:
   паритет источника, подхват `.env` профиля в субпроцессе, ошибка без `gate.py`,
   обновление при существующей джобе, обновление в `upgrade`), `EXIT=0`.
6. Полный набор `python -m pytest` → без падений, `EXIT=0`, `passed` ровно на 5 больше
   baseline, снятого ДО правок.
7. Живая проба в пустом по `STEP_PIPELINE_*` окружении: RED — скрипт без профильного
   `.env` печатает «[notify] нет токена/чата»; GREEN — установленный скрипт ту же строку
   не печатает и уведомление о закрытии шага реально приходит в чат владельца.

Решения, принятые за тебя (не переигрывать):

- D1. Источник текста — файл `proj.ENGINE_SRC / "tick.py"`; имя `TICK_SCRIPT` сохраняется

- D2. Установка пишет БАЙТЫ файла движка (`write_bytes`), а не строку через `write_text`:

  побайтово равным движку. Инвариант: `sha256` установленного скрипта = `sha256`

- D3. `ensure_cron` пишет скрипт ВСЕГДА (кроме `--no-cron`), до проверки существующей

  не повторяется.
- D4. `upgrade` обновляет скрипт только при наличии `.pipeline/cron.json`; профиль
  драйвера берётся первым из `roles_from_config(proj.read_config(project))`
  (`setup_flow.py:493-503`). Итоговая строка `:376` меняется на честную: джоба не
  тронута, тик-скрипт обновлён (или «не обновлялся: проект без cron»).
- D5. `HERMES_HOME` как источник `.env` не добавляется; `engine/tick.py` не правится.
- D6. Живая проба: ровно одно реальное сообщение в чат владельца (закрытие шага в
  одноразовом проекте). Реальную джобу по репозиторию не запускать.
- D7. Версия плагина и `CHANGELOG.md` не двигаются (см. «Запрещено»).

Образец стиля и формы: `docs/prompts/2026-11-03_1-S15_prompt.md` §5-§6 (задачи с адресами
и гейты с ожидаемыми числами). Копировать структуру, не смысл.

## 5. Что сделать (задачи)


и комментарий с причиной: «копия разошлась с движком 03.11.2026 (sha256 c11840c3… против
b7d98376…), тик молча возвращал 0 при отсутствии gate.py».

### Задача 2. Обновление при существующей джобе (D3)

### Задача 3. Обновление в `upgrade` (D4)

## 8. Формат отчёта

Отчёт — в карточке (`kanban_complete`), до закрытия шага, по порядку и с числами:

1. `git diff --stat` и `git show --stat` коммита шага (sha и сообщение), пуш подтверждён.
2. Что сделано по задачам 1-5: адреса изменений (`path:line`), как теперь берётся текст
   тика, где именно происходит запись в `ensure_cron` и `upgrade`, какие строки лога
   печатаются.
3. Гейты 1-7: команда, итоговая строка, число, `EXIT` для каждого; для гейта 5 — два
   хеша; для гейта 6 — RED и GREEN отдельными абзацами.
4. Числа тестов: baseline полного набора до правок, факт после, дельта ровно +5;
   `tests/engine/test_tick.py` 15; `tests/test_setup_flow.py` 19 без правок.
5. Решения, принятые самостоятельно, с причиной: точная форма констант (`TICK_SOURCE`,
   `TICK_SCRIPT`), почему запись байтами, где именно в `upgrade` взялся драйвер, как
   в тесте 3 воспроизведено отсутствие `gate.py`.
6. Что сознательно не сделано: `COMMANDS_SCRIPT`, `HERMES_HOME`, правки движка, версия,
   `CHANGELOG.md`, переустановка плагина, обновление `.pipeline/` владельцем,
   реальная джоба по репозиторию — и почему.
7. Расхождения с планом, названные явно: «5 passed» против фактических 15 (§2.4), `-q`
   из плана против `pytest.ini:3`, `engine/tick.py` без правок при том, что план его
   называет файлом шага (§2.1), и подтверждение граблей из `CONTEXT.md:133-137` живой
   пробой.
8. Отклонения от промта и открытые вопросы.

Язык отчёта — русский; вывод команд — не более 200 строк на команду (большой вывод в
файл и `grep` по нему).

## 9. Вопросы

1. Живая проба отправляет одно реальное сообщение в чат владельца — вариант A (рекомендую:
   только так «Готово» шага доказывается буквально, цена — одно сообщение от одноразового
   проекта) или вариант B (ограничиться локальным доказательством подхвата переменных,
   отправку проверит владелец; цена — шаг закрывается с оговоркой, что канал не проверен
   из контекста джобы).
2. Обновление в `upgrade` ограничить проектами с `.pipeline/cron.json` — вариант A
   (рекомендую: не пишем в профиль там, где cron не заводили; цена — у проекта без метки
   скрипт не обновится) или вариант B (обновлять всем проектам; цена — `upgrade` начнёт
   создавать файл в профиле у проектов, поставленных с `--no-cron`).

## 10. Ревью (обязательно)

Шаг не закрывает исполнитель: после гейтов — независимое ревью ролью `reviewer`
(скилл `pipeline-reviewer`) по плану `docs/plans/1-stabilnost.md` §S17 и по коду.
