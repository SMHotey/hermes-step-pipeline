## 1. Роль и цель

Ты — разработчик плагина `hermes-step-pipeline` (Python 3.11, только stdlib и Hermes).
Результат: в системный промт новой сессии попадает короткий раздел
`step-pipeline-planning`, текст которого зависит от состояния проекта, а в текущей сессии
загрузка скилла `pipeline-plan-authoring` блокируется, когда режим планировщика выключен.

Конкретно:
1. Новый модуль `step_pipeline/prompt_section.py` с чистой функцией
   `render_section(session_info) -> str` (три состояния: включён, выключен, проект без
   конвейера) и колбэком `on_pre_tool_call(...)` для хука `pre_tool_call`.
2. `step_pipeline/__init__.py` регистрирует секцию
   (`register_system_prompt_section("step-pipeline-planning", prompt_section.render_section)`)
   и хук (`register_hook("pre_tool_call", prompt_section.on_pre_tool_call)`); логики в
   `__init__.py` нет — только проводка.
3. `step_pipeline/plugin.yaml` объявляет `provides_hooks: pre_tool_call` — без этого
   `hermes plugins validate` краснеет (замер в п. 2).
4. Вето: при выключенном режиме `skill_view` для `pipeline-plan-authoring` возвращает
   `{"action": "block", "message": ...}` с причиной «режим планирования выключен,
   включить — hermes pipeline plan-mode on»; при включённом — `None`; если проект не
   найден — `None` без записи в лог; любая внутренняя ошибка — `None` с одной строкой
   в лог, но не исключение (этот хук в Hermes fail-closed).
5. Ровно восемь тестов в двух новых файлах, написанных ДО кода: 4 в
   `tests/test_prompt_section.py`, 4 в `tests/test_skill_gate.py`.

# ожидается: id секции и её регистрация, регистрация хука, provides_hooks в манифесте,
# константы SKILL_NAME/BLOCKED_REASON в модуле

## 7. Формат отчёта

По-русски, до и после коммита, по порядку: `git status --porcelain` до коммита → `git diff --stat`
после `git add` → что добавлено в `prompt_section.py` (константы, `_project_from_cwd`,
`render_section`, `on_pre_tool_call`, обработка ошибок) → что изменено в `__init__.py` (импорт,
две регистрации, docstring'и) → что добавлено в `plugin.yaml` → RED-прогон (команда, `EXIT`,
фактическая итоговая строка) → GREEN-прогон (8 passed, `EXIT`) → полный прогон (фактическое
число passed, `EXIT`) → вывод `hermes plugins validate step_pipeline` с `EXIT` → вывод `grep`
из §5 → подтверждение, что `plan_mode.py`, `project.py`, `cli.py`, `ui_server.py`, движок,
существующие тесты, `docs/` и версия не тронуты → самостоятельные решения с причиной → что
сознательно не сделано (развёртывание в профиль, версия, `CHANGELOG`, скилл S5) → отклонения
от промта → sha коммита и ветка пуша.
