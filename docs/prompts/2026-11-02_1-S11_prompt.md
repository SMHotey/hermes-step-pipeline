## 1. Роль и цель

Ты — разработчик плагина `hermes-step-pipeline` (Python 3.11, зависимости рантайма —
только stdlib и Hermes). Код, комментарии, коммит и отчёт — по-русски.

Цель шага: манифест и репозиторий перестают расходиться с реальностью. Сейчас плагин
живёт под двумя именами одновременно: `name: step-pipeline` в манифесте, каталог
`plugins/step_pipeline` на диске, `plugins update step-pipeline` в README и
`plugins enable step_pipeline` в install-скриптах. Часть команд работает только по
одному из имён, часть — только по другому, поэтому половина README не выполняется.

Готово = во всех командах README и обоих install-скриптах одно имя `step_pipeline`,
и это имя работает от установки до удаления (проверяется на изолированном
`HERMES_HOME`); `hermes plugins validate step_pipeline` → `Validation passed.`;
`LICENSE` (MIT) в корне и упомянут в README; в манифесте нет мёртвых ключей
`project_root` и `ui_port`, а порт UI живёт в `pipeline.json` проекта
(значение по умолчанию — в шаблоне); `git status` не показывает ни `.pipeline/`,

(`<hermes_home>\hermes-agent\hermes_cli\plugins_cmd.py`):

- `_require_installed_plugin` (`:463`) ищет каталог `plugins/step_pipeline` внутри

## 6. Стоп-сигналы

Останавливаться и докладывать (без «адаптирую по смыслу»), если:

1. `grep -rn "project_root\|ui_port" step_pipeline/*.py step_pipeline/engine/*.py`
   покажет чтение этих ключей из конфига плагина (в recon таких чтений нет) —
   удаление ключей изменит поведение, а не только манифест.
2. На изолированном доме (§5) `hermes plugins list` показывает не `step_pipeline`,
   `enable step_pipeline` пишет в конфиг другое имя, или `step-pipeline` остаётся
   рабочим алиасом: модель резолва отличается от recon — дальше не менять.
3. `hermes plugins validate` падает или выдаёт новое замечание, и починить это можно
   только правкой кода плагина/движка: гейт не «зеленеют» правкой кода.
4. Любой существующий тест краснеет по причине, не связанной с шагом (в дереве чужая
   правка `docs/CONTEXT.md`): назвать тест и ошибку, не править тест.
5. Проверка имени требует правки живого профиля Hermes (переустановка, `plugins
   enable` в `profiles/*`): чужие профили трогать нельзя — фиксировать как остаток
   для владельца.
6. Для `.gitignore` проектов-потребителей или для копирования `docs/templates/`
   требуется правка `setup_flow.py`: это отдельный шаг, в объём S11 не входит.

Формат доклада: что обнаружено (файл + строки), команда и её вывод, варианты с ценой,
рекомендация.

## 7. Формат отчёта

До закрытия шага, по порядку и с числами:

1. `git diff --stat` и `git show --stat` коммита шага (sha и сообщение).
2. Что и где изменено — по файлам, одной строкой на файл, с адресом `path:line`.
3. Доказательство «одного имени»: вывод `plugins list` / `show` / `enable` / `disable`
   на изолированном доме и строка из его конфига.
4. Гейты: команда, число (`5 passed`, `3 passed`, `208 passed`) и `EXIT` для каждого;
   вывод `hermes plugins validate` и `hermes pipeline config --get ui_port`.
5. Гигиена: вывод `git check-ignore -v` (четыре строки) и `git status --short` после
   коммита, с явным перечислением того, что осталось чужим.
6. Решения, принятые самостоятельно, с причиной (в том числе почему менялось имя
   манифеста, а не каталог; почему `ui_port` не попал в `DEFAULTS` движка; почему

## 9. Ревью (обязательно)

Шаг закрывает не исполнитель. После кода, гейтов и коммита шаг уходит на независимое
ревью роли `reviewer` (скилл `pipeline-reviewer`): вердикт `APPROVE` или
`REQUEST_CHANGES` в `docs/reviews/1-S11.md`, первая строка файла — коммит шага в
обратных бэктиках. Ревьюеру доступны план и код (`plugin.yaml`,
`pipeline.json.example`, `README.md`, `LICENSE`, `.gitignore`, `install.sh`,
`install.ps1`, `CHANGELOG.md`, `pipeline.json`, два новых теста) и его собственные
прогоны; отчёт исполнителя источником фактов не считается — числа и вывод команд
проверяются самостоятельным прогоном гейтов §5, включая проверку имени на изолированном
доме. При `REQUEST_CHANGES` шаг остаётся открытым: находки правятся, ревью
повторяется; строка «ЗАКРЫТ» в журнале и коммит закрытия — только после `APPROVE`,
и журнал пишет страж.
