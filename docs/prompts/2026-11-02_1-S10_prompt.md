# Промт: план 1 / шаг S10 — покрытие подпроцессов и CI-гейты

План: docs/plans/1-stabilnost.md, §S10. Шаг: S10 (1 дн). Дата: 2026-11-02.
Репозиторий: C:\Users\malik\PycharmProjects\hermes-step-pipeline, ветка main.

## 1. Роль и цель

Ты — разработчик плагина hermes-step-pipeline (Python 3.11, только stdlib и Hermes).
Исполнитель: профиль pipeline. Код, комментарии и отчёт — по-русски.
Цель шага: покрытие измеряется честно, включая подпроцессы, и его падение валит сборку.

Готово = отчёт CI показывает gate.py не ниже 55 процентов (сейчас 22 — артефакт),
порог fail_under валит сборку при снижении, на ubuntu и windows одинаковый результат.

## 2. Факты

- pytest.ini: testpaths = tests, addopts = -q --import-mode=importlib. Покрытия нет.
- .coveragerc отсутствует.
- .github/workflows/ci.yml: один job tests, матрица ubuntu-latest и windows-latest,
  python 3.11 и 3.13; шаг "Манифест плагина" с условием command -v hermes, иначе
  молчаливое "шаг пропущен" — это и есть дефект, который шаг закрывает.
- Тесты e2e запускают gate.py подпроцессом (tests/engine/engine_kit.py, conftest.py),
  поэтому без поддержки покрытия подпроцессов gate.py всегда выглядит непокрытым.
- Замер на 02.11.2026: python -m pytest -> 200 passed (полный прогон 301 с).
  Число тестов в отчёте — замером, не арифметикой.
- Интерпретатор с pytest в репозитории: .venv/Scripts/python.exe (pytest установлен).

## 3. Что сделать

1. .coveragerc: source = step_pipeline, tests; omit для кэшей; branch = true;
   report fail_under — значение выше фактического агрегата (замерить и зафиксировать).
2. Покрытие подпроцессов: дочерние gate.py должны стартовать coverage сами.
   Рабочий приём — sitecustomize.py с coverage.process_startup() и переменная
   COVERAGE_PROCESS_START в окружении детей; прокидку env делать в тестовой
   инфраструктуре (engine_kit/conftest) — это разрешённое отклонение, объявить в отчёте.
3. CI: два job. tests — установка pytest и coverage, прогон
   coverage run -m pytest, coverage report --fail-under, выгрузка отчёта артефактом.
   manifest — отдельный job, который ставит hermes и запускает validate; если hermes
   установить нельзя, job падает с внятной причиной, а не пропускает проверку молча.
4. actions обновить до актуальных мажоров (checkout, setup-python), версии python
   оставить 3.11 и 3.13.
5. В docs/CONTEXT.md одна строка: фактический агрегат и план роста порога.

Не входит: изменение существующих тестов ради покрытия, сборка exe, установка пакетов
в системный python, bump версии плагина.
## 4. Гейты (запускать и приводить фактические числа)

    .venv/Scripts/python.exe -m coverage run -m pytest
    .venv/Scripts/python.exe -m coverage report
    .venv/Scripts/python.exe -m coverage report --fail-under=<порог>; echo EXIT=$?
    .venv/Scripts/python.exe -m pytest
    hermes plugins validate step_pipeline

Ожидается: полный прогон 200 passed; coverage report показывает gate.py не ниже 55
процентов; прогон с заниженным порогом даёт EXIT не 0 (доказательство, что порог
работает); validate — Validation passed.

## 5. Стоп-сигналы

Доложить, не подгонять, если: покрытие gate.py не удаётся поднять до 55 без правки
продового кода движка; для покрытия подпроцессов требуется менять поведение gate.py;
краснеет любой существующий тест; CI-правка требует секретов; число тестов расходится
с 200 и расхождение не объясняется чужими правками.
## 6. Отчёт и ревью

Отчёт: diff --stat; ключевые диффы (.coveragerc, sitecustomize, ci.yml, правки

заниженным порогом; полный прогон; validate; самостоятельные решения с причиной;
что сознательно не сделано; отклонения (прокидка env в тестовой инфраструктуре).
