## 4. Решения (приняты постановщиком; исполнитель их не пересматривает, спор — вопросом)

D1. «Известные ключи» = то, что панель правит: `project`, `board`, `driven_plans`, `require_prompt`, `runtimes.step|review|prompt`, `paths.plans|reviews|prompts|state`. Остальное (`profiles`, `skills`, `markers`, `step_id_regex`, `default_plan`, `kanban`, `git`, `notify`, `prefetch_prompt`, `prompt_review`, `max_fix_rounds`, `max_actions`, `ui_port`) не валидируется и не теряется. `profiles` панель не редактирует (`AGENTS.md`, «Границы»).

D2. `runtimes.*` — `^\d+[mh]$` и число больше нуля. Отклоняются `5 часов`, `45`, `3ч`, `0m`, `-5m`, пустая строка. Причина — факт 10.

D3. `paths.*` — относительный путь от корня проекта: непустой, без `..`, не выходит за корень; скрытые каталоги **разрешены** (`.pipeline/state` — умолчание движка, факты 11-12); абсолютный путь отклоняется с просьбой задать относительный. Свой помощник, а не `snap.safe_path`.

D4. Дифф и запись — один расчёт: сервер отдаёт `diff` и `content` (точный текст файла после сохранения), сохранение пишет ровно этот текст. Иначе дифф врёт.

D5. Резервная копия — одна: `.pipeline/state/pipeline.json.bak` (каталог `.pipeline/` в `.gitignore`), хранит байты файла до последнего сохранения. Откат пишет эти байты напрямую, без пересборки JSON.

D6. Предпросмотр на диск не пишет. Если после слияния текст файла не изменился — `changed: []`, `diff: ""`, пометка «изменений нет»; сохранение файл и копию не трогает.

D7. Битый или отсутствующий `pipeline.json` — отказ с объяснением, файл не тронут (C6).

D8. Статусы как сейчас: 200 — успех, 400 — отказ валидации с `{"ok": false, "error": …}`, 500 — исключение.

D9. **Проектная адресация.** `GET /api/config` выбирает проект через `_choose_project(self._query().get("project"))` и отвечает 400 тем же текстом, что и остальные GET, если id неизвестен. Действия `preview_config`, `save_config`, `revert_config` работают с тем `state`, который уже выбрал `POST /api/action` (`ui_server.py:978`), и свой проект из тела не перечитывают; ответ каждого действия содержит `project` (это делает общий обработчик, `:1003-1005`). Панель зовёт `/api/config` через `withProject(...)`, а действия — через `act()`, который кладёт `project` в тело сам. Тестовая проверка C8 — на двух проектах реестра (`write_registry`, `tests/helpers.py:1161`).

## 6. Что сделать

### 6.1. Ядро валидации (`ui_server.py`)

Рядом с `CONFIG_KEYS` (`ui_server.py:85`) добавь константы `RUNTIME_RE = re.compile(r"^\d+[mh]$")`, `RUNTIME_KEYS = ("step", "review", "prompt")`, `CONFIG_PATH_KEYS = ("plans", "reviews", "prompts", "state")`.

- `_path_error(root: Path, raw: object) -> str` — пустая строка, если путь годен, иначе объяснение по D3: `str(raw or "").strip()` с заменой `\` на `/`; пусто → «путь не может быть пустым»; абсолютный (`Path(...).is_absolute()`, буква диска `C:`, начало с `/` или `~`) → «нужен путь относительно корня проекта»; `..` среди частей → «путь вне корня проекта»; итог `(Path(root).resolve() / Path(*parts)).resolve()` вне корня → «путь вне корня проекта». Части, начинающиеся с точки, проверку проходят и **не отбрасываются** (`.pipeline/state` — законное умолчание движка; отбросить точку значит записать другой путь).
- `_validate_patch(cfg: dict, patch: dict, root: Path) -> tuple[dict | None, list[str], list[str]]` — возвращает (`candidate`, `errors`, `notes`). Пустой `errors` = годно. Тексты ошибок начинаются с имени ключа и двоеточия: `runtimes.step: …`, `paths.plans: …`, `board: …`, `driven_plans: …`. Все ошибки собираются списком (панель показывает все сразу), но действие считает отказом любую.
- `notes` — не блокирующие замечания, их панель показывает рядом с диффом: каталог из `paths.*` не существует («каталог docs/plans не существует — файлов в нём не найдётся»), `driven_plans` пуст («страж не поведёт ни одного плана»), `project` пуст в файле и не задан в патче. `notes` не мешают сохранению.
- Правила по ключам (только те, что есть в патче; чужие ключи файла не судятся): `project`, `board` — `str().strip()`, пусто → отказ; `require_prompt` — bool; `driven_plans` — строка через запятую → список, каждый элемент `*` или цифры (факт 13), иначе `driven_plans: элемент должен быть * или номером плана`; `runtimes.*` — `RUNTIME_RE` и `int(...) > 0` (D2), лишние подключи `runtimes` сохраняются как есть; `paths.*` — `_path_error` (D3), лишние подключи сохраняются.
- Слияние — поверх прочитанного словаря: `cfg[key] = value`, `runtimes`/`paths` — `{**old, **new}`. Не пересобирать словарь с нуля: иначе теряются неизвестные ключи (C6).

### 6.2. Предпросмотр: действие `preview_config`

`act_preview_config(state, payload) -> dict`:

- патч — `payload.get("config")`; не объект → `{"ok": False, "error": "config должен быть объектом"}`;
- читать файл **байтами** (`(state.project / "pipeline.json").read_bytes()`), чтобы кириллица и отсутствие `\n` в конце пережили круговой рейс; нет файла или `JSONDecodeError` → отказ по D7 («pipeline.json не разбирается как JSON: … — правка отклонена, файл не тронут»);
- `candidate, errors, notes = _validate_patch(...)`; `errors` непуст → `{"ok": False, "error": "\n".join(errors)}`;
- `content = json.dumps(candidate, ensure_ascii=False, indent=2) + "\n"` — ровно формат `proj.write_config` (`project.py:184-186`);
- `diff` — `difflib.unified_diff(current_text.splitlines(True), content.splitlines(True), fromfile="pipeline.json (сейчас)", tofile="pipeline.json (после сохранения)", n=3)`, склейка `"".join`; больше 300 строк — обрезать и дописать строку «дифф обрезан: всего N строк»;
- ответ: `{"ok": True, "changed": [...], "diff": ..., "content": ..., "notes": [...]}`. `changed` — имена ключей патча, порядок — как в патче;
- проект — из аргумента `state` (D9), файл берётся по `state.project`, а не по корню сервера;
- на диск ничего не писать (проверяется тестом по байтам);
- регистрация: `ACTIONS["preview_config"] = act_preview_config` (`ui_server.py:385-394`).

### 6.3. Сохранение: переписать `act_save_config`

- Валидация — тем же `_validate_patch`, что и предпросмотр: один источник правил, иначе панель и API разойдутся.
- Файла нет / не разбирается → отказ (D7), поэтому `proj.read_config` (глотает ошибку) для решения о записи не годится: читай файл сам и разбирай JSON явно.
- Собрать `content` тем же способом, что в 6.2; если `content.encode("utf-8")` совпадает с текущими байтами — `{"ok": True, "changed": [], "noop": True, "note": "изменений нет"}` без записи и без копии (D6).
- Копия до записи: `backup = state.project / ".pipeline" / "state" / "pipeline.json.bak"`; `backup.parent.mkdir(parents=True, exist_ok=True)`; `backup.write_bytes(current_bytes)`.
- Запись: `proj.write_config(state.project, candidate)`; сразу после — перечитать файл и разобрать JSON. Не разобрался — вернуть байты из копии (`path.write_bytes(current_bytes)`) и отдать `{"ok": False, "error": "записал и не смог прочитать — вернул прежний файл"}`.
- Ответ: `{"ok": True, "changed": [...], "config": candidate, "backup": {...}}` — структура `backup` та же, что в `GET /api/config` (6.5).
- Чтение-проверка-запись — под `state.lock`; `state.note(...)` вызывать **строго после** выхода из `with`: `note()` берёт тот же `Lock`, а он не реентрантный — вложенный захват повесит запрос навсегда.

### 6.4. Откат: действие `revert_config`

`act_revert_config(state, payload)`:

- копии нет → `{"ok": False, "error": "резервной копии нет — откатывать нечего"}` (400);
- копия не разбирается как JSON → `{"ok": False, "error": "резервная копия повреждена — откат не выполнен, файл не тронут"}` (файл при этом не пишем вовсе);
- иначе `(state.project / "pipeline.json").write_bytes(backup.read_bytes())` — без пересборки JSON, без `write_config` (C5, D5); ответ `{"ok": True, "restored": True, "bytes": N, "sha256": ...}`;
- откат новую копию не создаёт: повторное сохранение перезапишет её — «одна кнопка» именно так и работает;
- `state.note("pipeline.json восстановлен из копии побайтово")` — вне `with state.lock`;
- регистрация: `ACTIONS["revert_config"] = act_revert_config`.

### 6.5. Маршрут `GET /api/config` (с адресацией проекта)

`_get_config(self)` в классе `Handler` плюс ветка в `do_GET` (`ui_server.py:745-796`), рядом с `/api/setup`:

- `if not self._local_only(): return` — как у остальных GET (`ui_server.py:490`);
- `state = self._choose_project(self._query().get("project"))`; `state is None` → `return` (метод уже отправил 400 со списком доступных, `ui_server.py:558-574`);
- файл — `state.project / "pipeline.json"`, копия — `state.project / ".pipeline" / "state" / "pipeline.json.bak"`;
- ответ: `{"ok": true, "project": {"id": state.id, "name": state.name}, "preview": state.preview, "path": str(...), "config": {...}, "errors": [...], "backup": {"exists": bool, "path": ".pipeline/state/pipeline.json.bak", "bytes": N, "saved_at": "2026-11-05T10:00:00"}}`;
- битый файл → `config: {}` и `errors: ["pipeline.json не разбирается: …"]`, статус 200: маршрут читающий, панель должна нарисовать форму и объяснить, почему правка не пройдёт;
- в предпросмотре маршрут работает и отдаёт `config: {}`, если файла нет;
- секретов в `pipeline.json` нет (в `notify` только имена env-переменных) — файл отдаётся целиком, это и есть ответ на «что сейчас в конфигурации».

### 6.6. Форма настроек (`ui/index.html`)

- Блок «Каталоги» в диалоге `id="settings"`: четыре поля `path_plans`, `path_reviews`, `path_prompts`, `path_state`, подпись «от корня проекта».
- Кнопка «Проверить» (`id="config-check"`): собирает тот же патч, что и сохранение (включая `paths`), шлёт `action: "preview_config"` и рисует дифф в `id="config-diff"` (моноширинный, строки `+` и `-` разными классами), показывает `notes` списком. Запрос идёт через `api()` напрямую, **не через `act()`**: `act()` после ответа перезагружает снимок и показывает тост «готово», а проверка ничего не меняет и тоста не заслуживает.
- «Сохранить» (`id="save-config"`) активна **только после** успешной проверки; любое изменение поля формы (`addEventListener("input")` на `#form-config`) сбрасывает дифф и гасит кнопку — иначе сохранится не то, что показано (C3).
- «Вернуть как было» (`id="config-revert"`) в том же диалоге: активна, когда `GET /api/config` отдал `backup.exists === true`, подпись содержит дату копии; после нажатия форма перезагружается из `/api/config`, дифф очищен.
- Открытие диалога грузит значения из `GET /api/config` (`api(withProject("/api/config"))`), а не из снимка: `paths` в снимок не попадают (факт 7). Флаг `__configLoaded` продолжает работать для снимка — диалог читает `/api/config` при каждом открытии и после смены проекта.
- Ошибку валидации показывать в диалоге в `id="config-error"` (рядом с диффом), а не только тостом: объяснение длиннее строки тоста.

## 8. Стоп-сигналы

Останавливайся и докладывай, не «адаптируй по смыслу»:

С1. На старте изменены файлы шага или движка: `git status --porcelain` содержит `M`/`A` по `step_pipeline/ui_server.py`, `step_pipeline/ui/index.html`, `tests/test_ui_server.py`, `step_pipeline/engine/**`, `step_pipeline/plugin.yaml`, `tests/helpers.py`. Работать поверх чужих незакоммиченных правок нельзя — доложи, чьи они. Неотслеживаемые `docs/reviews/*.md` стоп-сигналом НЕ являются: это отчёты ревью постановок, они так и живут неотслеживаемыми (уточнение после ревью постановки от 05.11.2026).

С2. Адрес или символ из постановки разошёлся по **смыслу** (например, `act_save_config` уже валидирует `runtimes` или уже пишет копию). Сдвиг номеров строк — не повод останавливаться, ищи по имени символа.

С3. Для исполнения нужен файл вне трёх разрешённых — в первую очередь `project.py` (формат `write_config`), `snapshot.py` (`safe_path`), `tests/helpers.py` (реестр проектов). Нужен — стоп с обоснованием.

С4. Зелёные тесты достижимы только ослаблением существующего теста или сужением прежнего контракта (`test_save_config`, `test_save_config_rejects_empty_board`, коды 200/400). Стоп.

С5. Гейт красный по посторонней причине: нет `.venv`, падает чужой тест, нет `hermes` для Г4, не создаётся worktree для Г2. Стоп и доложи факт — чей тест, что упало, полный вывод.

С6. Тянет поправить движок (`engine/config.py`, `engine/gate.py`), чтобы «валидация была в одном месте». Стоп: движок копируется в проекты, его объём — не этот шаг.

С7. Проверка требует записи в реальный `pipeline.json` репозитория или в реальный профиль Hermes. Стоп: всё проверяется на tmp-проектах тестов, живой файл не трогается.

С8. Хочется расширить формат `runtimes` сверх D2 (суффиксы `s`/`d`, `1h30m`) или разрешить абсолютные пути. Стоп: это вопрос границ владельцу, а не молчаливое расширение.

С9. Для проектной адресации требуется правка `_choose_project`, `State`, реестра или `project.py` — стоп: в этом шаге адресация только используется, не переделывается (D9).

## 9. Формат отчёта

Отчёт — в карточку борды, по-русски, по пунктам; сначала отчёт, затем коммит, sha — отдельной строкой после коммита.

1. Что сделано — по задачам 6.1-6.8, с адресами `path:line` по **своим** правкам (не по постановке).
2. Г1: команда, фактическое `passed/failed/error`, число новых тестов; рядом — база 76 на HEAD.
3. Г2: полный вывод RED-прогона (число `failed`/`error`, код возврата pytest), команда worktree и её очистка.
4. Г3: команда, фактическое `passed/failed`, собрано тестов (ожидание 408 + N).
5. Г5: вывод `git status --porcelain` (только два `??` по `docs/reviews`) и `git show --stat` (три файла).
6. Список добавленных тестов: одна строка на тест — что именно утверждает; отдельно назвать тест C8.
7. Что осталось и чего не делал (вне объёма) — честно, без «потом доделаю».
8. Изменившиеся по ходу факты дерева — какие строки съехали и как искал.

Коммит — один, после зелёных гейтов, сообщение в стиле `git log --oneline` репозитория: `feat(ui): правка конфигурации с валидацией, диффом и откатом`. `docs/reviews/*.md` в коммит не добавлять. Слово «ЗАКРЫТ» в журнале плана не ставить: это делает страж после APPROVE.

## 10. Вопросы

Открытых вопросов нет: развилки закрыты решениями D1-D9, работать можно без ответа владельца. Два места, где решение могло быть иным, названы с ценой — если владелец ответит до старта, следуй его ответу.

В1. Формат `runtimes` (D2): принято `Nm`/`Nh`. Цена расширения (`1h30m`, `90s`, `3d`) — свой разбор и три-четыре новых теста; канбану формат безразличен, отказ нужен только ради ранней ошибки.

В2. Резервная копия (D5): одна, до последнего сохранения. Цена истории (несколько копий с метками времени) — каталог, лимит по числу и выбор версии в форме; для «вернуть как было» достаточно одной.

## 11. Ревью (обязательно)

Шаг закрывает независимое ревью роли `reviewer` (`pipeline-reviewer`), не исполнитель.

- Что ревьюер получает: план (`docs/plans/3-panel.md`, §S7), эту постановку, код и тесты в коммите. Отчёт исполнителя — не источник фактов: каждое утверждение проверяется по дереву.
- Что проверяется в первую очередь: C1-C8 против кода, а не против отчёта; адресация проекта в `GET /api/config` и в действиях (C8, D9) — отдельно, включая ответ 400 на неизвестный id; «дифф не врёт» (D4) — сверка `content` предпросмотра с записанными байтами; побайтовость отката на файле без завершающего перевода строки; сохранность неизвестных ключей и подклечей; RED-прогон Г2 (новые тесты падают на HEAD); отсутствие правок вне трёх файлов и отсутствие `docs/reviews/*.md` в коммите.
- Вердикт: APPROVE — можно ставить «ЗАКРЫТ» в журнале и коммитить закрытие шага; REQUEST_CHANGES — перечень находок с адресами.
- При REQUEST_CHANGES шаг остаётся открытым: находки правятся, гейты Г1-Г5 прогоняются заново, ревью повторяется. Исполнитель шаг не закрывает никогда — ни при зелёных тестах, ни при устном согласии.
