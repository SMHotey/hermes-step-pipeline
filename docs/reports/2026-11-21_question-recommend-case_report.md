# Отчёт: страж терял рекомендацию вопроса при «Рекомендация» с большой буквы (0.37.4)

Дата: 21.11.2026. Ветка `main`, коммит правки `c50766a`, тег `v0.37.4`, релиз
https://github.com/SMhotey/hermes-step-pipeline/releases/tag/v0.37.4.
Источник: карточка шага S4 плана 3 (живой проект), символ `gate.py::QUESTION_RECOMMEND_RE`.

## 1. Что сделано

1. `gate.py::QUESTION_RECOMMEND_RE` — флаг `re.I`, как у соседнего `QUESTION_NO_RECOMMEND_RE`.
   Шаблон не менялся: форма `— Рекомендация: B.` даёт `B`, `— рекомендации нет` даёт пустую
   рекомендацию. Причина в комментарии рядом с шаблоном.
2. `tests/engine/test_question_recommend_case.py` — пять случаев хвоста вопроса из карточки,
   ожидания `A`, `A`, `B`, `A`, ``.
3. Версия `0.37.4`, запись в `CHANGELOG.md`, тег, GitHub Release (`update.latest` читает
   релизы, а не только теги).
4. Движок пересобран: профильные копии плагина (8 профилей) и копии в двух живых проектах
   подняты `0.37.3 → 0.37.4` через `hermes pipeline setup --upgrade`.

## 2. Проба: было и стало

Вывод `parse_question_line` на одной строке (`— <хвост>` после текста вопроса):

| хвост строки вопроса | до правки | после |
|---|---|---|
| `— рекомендация A` | `A` | `A` |
| `— Рекомендация A` | `` | `A` |
| `— Рекомендация: B.` | `` | `B` |
| `. Рекомендация A.` | `` | `A` |
| `— рекомендации нет` | `` | `` (верно) |

## 3. Миграция уже записанных строк: почему не срабатывает

`register_questions` приводит уже записанную строку к полному тексту (`_question_truncated_prefix`)
только когда пары «шаг + текст» ещё нет. На живом `Q-1` из файла вопросов миграция не
срабатывает по трём причинам, каждая проверена на настоящей строке:

- **Текст уже полный.** Разбор отчёта заново даёт ровно тот текст, что лежит в файле
  (246 символов, совпадение посимвольно), поэтому ключ дубликата совпадает и цикл уходит
  по `continue` (ветка миграции ниже него не выполняется).
- **Строка закрыта.** `_question_truncated_prefix` требует статус `открыт`; у `Q-1` статус
  `закрыт` (ответ `A` дан владельцем), поэтому даже на обрезанном тексте функция отвечает
  `False`. Проверка на синтетической паре: `открыт` + обрезанный текст → `True`,
  `открыт` + полный текст → `False`, `закрыт` + обрезанный → `False`.
- **Пустая рекомендация — не текст.** Миграция переносит `text`, `options` и `recommend`
  вместе, то есть чинит строку, у которой обрезан хвост. Строку, у которой текст целый, а
  потеряна только рекомендация, она не трогает по устройству.

Вывод: у живых открытых вопросов с полным текстом и пустой рекомендацией обратной заливки
нет — ни этой правкой, ни миграцией. Отдельная правка (перечитывать рекомендацию у открытых
строк при повторном чтении отчёта) не делалась: карточка запрещает её без решения владельца.

шёл 39.5 мин под нагрузкой — тест по времени на грани таймаута.

## 5. Что осталось

- **Версия `0.37.3` вышла без тега и без GitHub Release** (теги идут `v0.37.2 → v0.37.4`).
  `0.37.4` её перекрывает, `update.latest` теперь `0.37.4`, поэтому копии у потребителей
  сойдутся; отдельно тегировать `0.37.3` задним числом не стал — это решение владельца.
- **Обратная заливка рекомендации у уже записанных открытых строк** — решение владельца (§3).
- Изменения шага 10-S2B (порог подробности, замер вопроса) доехали до потребителей тем же
  `0.37.4`: до этого релиза они лежали на `main` без версии.
