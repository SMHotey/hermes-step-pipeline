# 17-S3 — снимок убитой по лимиту попытки

Дата: 24.11.2026. План: `docs/plans/17-samorazvitie-plagina.md`, шаг S3.
Постановка: `docs/prompts/2026-11-24_17-S3_prompt.md`.

## Симптом, который закрывался

20.11.2026 шаг 2-S6 убит на 91-й минуте при лимите 60 минут. В карточке осталась одна
строка `elapsed 5491s > limit 3600s`; изменённый файл на диске был, но следующая попытка
об этом не знала и начинала с нуля (run 101 → 102 → 103).

## Что сделано

`step_pipeline/engine/gate.py`

- `collect_kill_snapshot(p, card, row, step=None)` — снимок: `git status --porcelain`
  (изменённые / созданные пути), первые пять строк `git diff --stat`, строка метрики
  попытки целиком, три последних инструмента из `agent.log` в окне попытки.
  Окно считается тем же правилом, что у метрики: запись прогона по `run_id` с допуском
  `WINDOW_PAD`, иначе метка старта карточки + метка строки метрики.
- git молчит дольше `KILL_SNAPSHOT_GIT_TIMEOUT = 10` с, вернул ненулевой код или не
  ответил — снимок собирается по списку «Файл:» шага (`source: "step_files"`), дерево
  не обходится (стоп-сигнал шага).
- `kill_snapshot_text(entry)` — блок «Продолжай с этого»: лимит и время снимка, пути,
  diff, числа метрики, хвост инструментов, чего делать. Дата — `ДД.ММ.ГГГГ ЧЧ:ММ:СС`,
  длительности по-русски (`9,6 с` / `5,1 мин` / `1 ч 32 мин`), больше 20 путей — первые
  двадцать и строка «ещё N файлов не показаны», пустые данные — строки-заглушки.
  Битая запись (не словарь, нет шага, неизвестный источник, файлы не списками) — пустой
  блок, а не половина снимка.
- `write_kill_snapshot` / `load_kill_snapshots` / `kill_snapshot_entry` — файл состояния
  `<state_dir>/kill_snapshot.json`, ключ `<план>:<шаг>`; первый же ключ, а не отметка на
  карточке: он же читается телом следующей попытки и переживает идемпотентный `create`.
- `kill_snapshot_hook(p, ctx, say=None)` — вызывается из `run_gate` в блоке метрики:
  находит последнюю строку «убит по лимиту» (`killed_by == "runtime"`) по карточкам шага,
  кладёт снимок и один комментарий в карточку на пару «карточка + прогон». Запасной путь:
  прогонов в борде нет — лимит берётся из `last_failure_error` карточки тем же шаблоном
  `step_metrics.LIMIT_TEXT_RE`. Отказ `kanban comment` отметку не ставит — следующий тик
  дошлёт. Ни один сбой снимка тик не валит и вердикт стража не меняет.
- `step_card_body`: блок «Продолжай с этого» стоит до «Цель:», печатается только если
  снимок есть и шаг ещё не закрыт в журнале.

`step_pipeline/engine/step_metrics.py`

- `_card_runs` → `card_runs` (публичное имя): тем же разбором `task_runs` пользуется
  снимок, окно событий лога считается одним кодом, а не копией.

`tests/engine/test_kill_snapshot.py` — 16 тестов: файлы из дерева, хвост инструментов,
комментарий в карточку, один комментарий на попытку, досылка после отказа CLI, чистое
дерево, блок в следующей карточке, закрытый шаг без блока, тело без снимка, точный текст
по числам, битая запись, запасной путь по файлам шага при молчании git, усечение списка
путей, запасной путь по ошибке карточки, `execute=False` ничего не пишет.

Готово по контракту шага: на фикстуре «шаг убит по лимиту, в дереве изменённые файлы»
карточка получает комментарий со списком файлов и числами метрики, а тело следующей
попытки несёт блок «Продолжай с этого» с теми же путями. Обратная сторона тоже покрыта:
чистое дерево даёт «файлов нет», молчащий git — список файлов шага, повторный тик второго
комментария не пишет.
