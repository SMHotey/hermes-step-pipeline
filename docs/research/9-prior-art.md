# План 9 — разведка: как закрывать шаг по прогону, а не по вердикту модели

> Артефакт разведки к `docs/plans/drafts/9-ispolnimaya-priyomka.md`. Дата: 14.11.2026.
> Объект: практики «исполняемой приёмки» (executable acceptance), машинночитаемых находок,
> ограничения контекста и замера автономности. Метод: GitHub API (звёзды, дата коммита,
> лицензия — запрос `api.github.com/repos/<repo>` 14.11.2026), README и документация
> проектов, замер собственного дерева.
>
> Замер дерева 14.11.2026 (парсер `next_step.plan_steps` по 8 планам, 78 шагов): критерий
> `Готово =` содержит команду-проверку у 6 шагов из 78 (7,7 %); у остальных 72 (92 %) —
> проза, которую может оценить только модель-ревьюер. Движок закрывает шаг по
> `APPROVE` + наличию коммита (`docs/CONTEXT.md` §5, инвариант 3), то есть по тексту
> вердикта, а не по прогону. Конституция п.7 требует обратного: «шаг закрывается по
> прогонам, а не по описанию прогонов».
>
> Внешних библиотек план не добавляет (инвариант «только stdlib и Hermes»), поэтому
> кандидаты оцениваются как источник механизма, а не как зависимость.

## Итог

Решение: go — четыре механики, все на stdlib, без новых зависимостей:
(1) пункт шага `Проверка:` — машиночитаемый список (команда, ожидание `exit 0` или
`содержит «…»`, таймаут, признак `slow`), его разбирает `next_step.py`, а не карточка;
(2) гейт **сам** прогоняет проверки перед закрытием шага и пишет доказательство в
`.pipeline/state/checks/`; отчёт исполнителя — для человека, источник истины — прогон
(иначе слабая модель «зеленеет» в тексте, не запуская команду);
(3) находки ревью и гейта получают код из закрытого словаря F01–F08 с адресом и
ожиданием — правка становится задачей с проверяемым результатом, а не пересказом;
(4) бюджет контекста: дайджест объявленных файлов шага вместо чтения репозитория,
и проверка «коммит не выходит за объявленные файлы» как находка F01.

Что отвергнуто и почему: Gherkin (второй язык описания, 3 дн, слабая модель теряет
связь с командой), отдельный рантайм/durable-движок (у нас файловое состояние и
идемпотентные ключи — плата 5 дн без выигрыша), мутационное тестирование в шагах
(цена 2 дн и минуты прогона на каждом шаге — только для релизных проверок),
нормализация через SARIF (формат чужой, нужна лишь идея `ruleId`).

Проверка: `python .pipeline/scout_report.py docs/research/9-prior-art.md` → PASS.

Решение: go — исполняемая приёмка, коды находок, бюджет контекста, метрики автономии.
