## Находки

- **[значимая, риск сопровождения]** `step_pipeline/setup_flow.py:291-304` + `:660` — обновление пишет в профиль драйвера,
  а профиль может быть общим у нескольких проектов (по умолчанию драйвер — `default`, см. `setup_flow.py:435`). Тогда `upgrade`
  проекта A перезаписывает `profiles/<драйвер>/scripts/pipeline_tick.py`, которым ходит cron-джоба проекта B, — при разных версиях
  плагина у A и B скрипт может «откатиться». На поведение шага не влияет (скрипт проектно-нейтрален: `gate.py` берётся из `workdir`
  или `PIPELINE_REPO`), поэтому шаг не блокирую; ожидание — решение владельца: либо зафиксировать «один драйвер-профиль на несколько
  проектов не поддерживается», либо писать скрипт только при отличии и с проверкой версии движка.
- **[стилистическая]** `step_pipeline/setup_flow.py:93` — между `install_tick_script` и `COMMANDS_SCRIPT` одна пустая строка вместо двух
  (PEP8 E305). Читаемость, не дефект.
- **[стилистическая]** `step_pipeline/setup_flow.py:79` — `TICK_SCRIPT` вычисляется чтением файла на импорте модуля: в повреждённой
  установке без `engine/tick.py` любая команда `hermes pipeline …` упадёт на импорте `setup_flow` с `FileNotFoundError` вместо
  понятной ошибки. `tick.py` входит в `ENGINE_FILES` (`setup_flow.py:34-36`), в норме файл есть; ожидание — чтение внутри
  `install_tick_script` (строка `TICK_SCRIPT` нужна только тестам) либо ленивое свойство.

Блокирующих находок нет.
