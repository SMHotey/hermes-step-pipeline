## Находки

1. [значимая] `step_pipeline/snapshot.py:1215` — признак `rate_limited` ставится по подстроке
   `rate`/`429` в тексте `summary`/`error`, из-за чего на живой борде 2 попытки из 177 получают
   `rate_limited: true` при `outcome = completed`: run 147 (в тексте отчёта ревью постановки
   есть «437-446/429-433») и run 164 (текст пересказывает находку «rate_limited нет в схеме»).
   Ожидается: признак по `outcome == "rate_limited"` либо по `\b429\b` / `rate.?limit`. Правило
   предписано постановкой (Р3, D9), то есть это дефект постановки, а не исполнения; в разметке
   поле не выводится (`label` и `bad` считаются от `outcome`), гейт шага не страдает.
2. [стилистическая] `step_pipeline/snapshot.py:1011` — `_current_run` берёт последнюю попытку
   без `ended_at`, тогда как D6 называет источником `current_run_id`. На живой борде
   расхождений нет (0 из 61 карточки плана 3). Ожидается: при непустом `current_run_id` брать
   попытку по нему, эвристику оставить резервом — иначе брошенная строка `task_runs` с
   `ended_at IS NULL` может стать «текущей».
3. [стилистическая] `tests/test_ui_server.py:2131`, `:2132`, `:2253` — формат метки
   («05.11.2026 12:47») нигде не проверяется литерально: обе стороны сравнения строит
   `snapshot._fmt_ts`. Ожидается одно утверждение по регулярке (рекомендация 3); фактический
   формат верен — проверен на живом ответе (`05.11.2026 14:30`).
4. [стилистическая] `step_pipeline/snapshot.py:1001` — третий резерв начала этапа сверх D6
   (сделано сверх постановки). Ожидается: либо назвать резерв в постановке, либо убрать; вреда
   нет — на живой борде `tasks.started_at` совпадает с минимумом `task_runs.started_at`.
5. [стилистическая] `step_pipeline/ui/index.html:721` — `tickRoles` и атрибуты `data-role-*`
   как второй механизм тика рядом с `[data-live]` из D11 (сделано сверх постановки). Ожидается:
   либо описать механизм в D11, либо свести к одному; сейчас оправдан пунктом 6.4 («обе
   таблицы тикают»), закрытые строки не трогаются.
6. [стилистическая] `step_pipeline/snapshot.py:1166` — IN-список режется по 400 параметров
   (сделано сверх D9). Ожидается: оставить как есть и упомянуть в постановке; поведение не
