## Находки

1. **[значимая]** `step_pipeline/engine/gate.py:986-994` против
   `docs/plans/4-planner.md:155-159` — для **уже идущего** плана унаследованная запись
   пишется при любом расхождении, не только при отсутствии записи. Моя проба D: запись
   с чужим хэшем (`f…f`) после одного прогона заменена фактическим хэшем с
   `inherited: true`, решение `create_step` — то есть «план изменён после утверждения»
   для идущего плана не блокирует. Это реализовано по постановке (§5.2.5) и является
   единственным работоспособным вариантом: страж сам перезаписывает файл плана при
   закрытии шага (`append_journal_row`, `gate.py:318-345`), поэтому хэш меняется на
   каждом закрытии, а пункт «Готово = для плана с закрытыми шагами … продолжает работу»
   иначе не выполнить. Ожидается решение владельца: дописать оговорку в план (изменение
   после утверждения «прощается» идущему плану) либо отдельным шагом обновлять запись
   утверждения при закрытии шага — тогда сверка хэша снова станет значимой и для идущих
   планов. Для этого шага правка кода не требуется.
2. **[значимая]** `tests/helpers.py:94-109,113,127-131` и `tests/test_plan_mode.py:18-26` —
   расширение объёма: два файла сверх «ровно шесть» постановки, причём `tests/helpers.py`
   был прямо запрещён. Изменения аддитивные (запись утверждения в фикстуре
   `install_project` + локальная фикстура с `approved=False`); по диффу ни одно
   утверждение чужих тестов не удалено, не ослаблено и не переписано. Причина по
   существу та же, что D8, и она верна: D8 закрывал только `tests/engine`, а плагинный
   слой строит проект через `tests/helpers.install_project`, и 8 тестов
   (`test_engine_e2e`, `test_tools`, `test_ui_server`) стали бы красными. Цена: общая
   плагинная фикстура теперь всегда пишет утверждение, поэтому путь «утверждения нет»
   на плагинном слое не проверяется (он покрыт тестами движка).
