## Находки

- [значимая] `step_pipeline/ui_server.py:552` — `State` соседа создаётся с
  `board=self.state.board`, то есть флаг `--board` сервера навязывается всем проектам
  реестра. В предпросмотре это ожидаемо (у проекта может не быть `pipeline.json`), но
  `hermes pipeline ui --board X` без `--preview` тоже принимается парсером
  (`cli.py:83`), и тогда сводка и снимок соседей читают чужую борду вместо своей из
  `pipeline.json` — карточки проекта показываются от другой борды. Ожидается: `board`
  сервера применяется к проекту сервера и к предпросмотру, у остальных `None` → борда из
  их конфига. Приёмку не блокирует: сценарий требует явного `--board`.
- [стилистическая] `tests/test_manifest_hygiene.py:22-23` — в `PLUGIN_SOURCES` добавлен
  `cli.py`, которого нет в D2 (там перечислены `project.py`, `setup_flow.py`, `doctor.py`,
  `ui_server.py`). Гейт стал мягче: ключ, упомянутый только в `cli.py`, теперь проходит
  проверку. Ожидается: список из четырёх файлов D2 — все текущие ключи проходят и без
  `cli.py` (`telegram_*` — через `env:`, `project_root` — `project.py`).
- [стилистическая] `step_pipeline/ui_server.py:688` — `data["project_id"] = state.id` в
  снимке сверх задачи 5 (там требуется только `installed`); `:599` — поле `error` в строке
  сводки сверх списка полей задачи 4. Вреда нет, но это расширение контракта API без
  постановки; страница `project_id` не читает (`index.html` — ни одного вхождения).
- [стилистическая] Бейдж `#project` (`index.html:183`, заполняется из `data.project`)
  показывает `pipeline.json.project`, а не имя из реестра: в живом прогоне select = «Бета»,
  бейдж = «demo» (оба фикстурных проекта объявлены как `demo`). Задача 7 обещает «имя
  выбранного проекта»; при расхождении имён в реестре и в `pipeline.json` панель показывает
  два разных имени. Ожидается: либо бейдж из `state.name`, либо явная строка в
  постановке/документации, что источник — `pipeline.json`.
- [стилистическая] `tests/test_ui_server.py:1260-1285` — тест «действие по A не меняет B»
  останавливает проект по умолчанию (`alpha`), поэтому игнорирование поля `project` в POST
  он бы не поймал; маршрутизация POST для не-дефолтного проекта доказана только косвенно
  (`tests/test_ui_server.py:1210-1230`: действие по `bare` → 400 «не установлен»). Мой живой
  прогон поведение подтвердил, но тест стоит усилить: действие по `beta` и проверка файла
  состояния `beta` (и отсутствия такового у `alpha`).

Блокирующих находок нет: контракт «Готово =» закрыт, запреты не нарушены, гейты зелёные
по моим прогонам.
