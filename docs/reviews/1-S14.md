## Находки

Блокирующих нет.

**[значимая] `gate.py:1493-1494` (вместе с `:1667`) — флаг `--max-actions` со значением
меньше 1 не перекрывает конфиг.** `main` передаёт `0`/отрицательное как есть, а `tick`
при `max_actions < 1` откатывается к `max_actions_of(cfg)`, то есть к файлу. Проба C:
конфиг `max_actions=3` + `--run --max-actions 0` → **2 действия** (`close_step`,
`create_step`), а не одно. Это расходится с D2 («флаг выше файла»): заданный флаг должен
побеждать, а недействительное значение — трактоваться как 1 (как в `max_actions_of`).
Ожидание: `limit = args.max_actions if args.max_actions is not None else max_actions_of(cfg)`
с приведением `< 1` к 1 в одном месте (или ошибка argparse на `< 1`). Действий по шагу
инвариант не нарушает, поэтому не блокирую.

**[значимая] `gate.py:1515-1519`, `:1582` — поле `retried` может описывать чужой план.**
В первом проходе `retried_any` перезаписывается результатом `retry_pending` каждого
посещённого плана, включая простаивающие; в старом коде `result["retried"]` принадлежал
плану, который выполнил действие. Проба E (два плана, у плана 1 отложенный коммит
падает, действие выполняет план 2): новый движок вернул `retried` плана 1
(`{'applied': False, 'detail': "pending commit всё ещё ждёт: git add: fatal: pathspec …"}`),
старый — `None`. Влияние: поле в `--json` и `acted` в `main` (`:1758`) — при чужом
неудачном коммите тик печатает статус в лог cron, хотя ничего не сделал; решения,
карточки и журнал не затронуты. Ожидание: `retried` относится к плану выполненного
действия (как раньше), неудачная попытка чужого плана в результат тика не попадает.
Существующие e2e-тесты этот край не покрывают, поэтому «поведение при 1 совпадает»
проверено ими лишь для однопланового случая — мой дифференциальный прогон подтвердил
совпадение по всем ключам, кроме этого края.

**[стилистическая] `gate.py:1765-1773` и `:47` — ветка `--run --plan` названа «тик
только по одному плану», но предел в ней не применяется.** `--run --plan 3
--max-actions 5` сделает одно действие. Либо применить предел к этой ветке, либо
сказать в докстринге/справке «одно действие по одному плану», чтобы формулировка не
обещала больше, чем делает код.

**[стилистическая] `tests/engine/test_max_actions.py:15` — неиспользуемый `import time`**
(используется только внутри строки-заготовки `FAST_STUB`). CI линтером не проверяет,
на прогоны не влияет.

**[стилистическая] `gate.py:1563-1565` — ветка «действие шага не адресует» недостижима:**
все не-idle решения `decide` содержат `step` (`_decide_base`, `:667-738`). Защитный код
не вредит, но мёртв.

**[стилистическая] Предел `LAST_ACTIONS_KEPT` (20) и обрезка списка не покрыты тестом** —
проверено чтением (`gate.py:123`, `:1473`). Задача 8 постановки такого теста не требовала;
отмечаю как запас на будущее, не как нарушение.
