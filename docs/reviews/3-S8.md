## Находки

1. [значимая] `step_pipeline/ui_server.py:1496` — id в ответе `POST /api/projects` берётся
   из файловой записи (`created["id"]`), а id в сводке считает память сервера, где уже есть
   проект по умолчанию. При совпадении имени нового проекта со slug каталога проекта
   сервера ответ расходится с реестром: проба `{"path": <каталог beta>, "name": "alpha"}`
   при сервере на каталоге `alpha` дала `project.id = "alpha"`, а `GET /api/projects` —
   строку `alpha-2`. Ожидается: после `_reload_registry()` брать id из свежей строки
   `self.registry` по `root`. Приёмку не блокирует: страница id из ответа не использует
   (`index.html:724` — тост по `name`), источник истины для неё — `GET /api/projects`.
2. [стилистическая] `tests/test_ui_server.py:1672-1675` (и `:1745-1752`) — комментарий и
   докстринг обещают проверку сброса кэша сводки (D4), но первый `GET /api/projects` идёт
   уже после `POST`: кэш холодный, и без строки `ui_server.py:1100` оба теста проходят (моя
   мутация — 2 passed). Ожидается: `get(url + "/api/projects")` перед `POST`, тогда сброс
   кэша станет несущей проверкой.
3. [стилистическая] `tests/test_ui_server.py:1881-1883` — блок 380 px режется до конца
   файла (`html[html.index("@media (max-width: 380px)"):]`), поэтому `overflow-x` и
   `grid-template-columns: 1fr` проходят и по правилам вне медиа-блока. Ожидается: резать
   по парной `}` блока.
4. [стилистическая] `tests/test_ui_server.py:1596-1930` — нет тестов на два пункта
   контракта: «неизвестные поля файла сохраняет» (C1) и «несуществующий каталог → 400»
   (C3, ветка `ui_server.py:1461`). Оба поведения работают — проверены моими пробами
