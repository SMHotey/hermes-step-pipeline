1. `step_pipeline/snapshot.py:36-38` — из `ACTION_LABELS` снята запись
   `"hold_risk": "ручной допуск"`. Её добавил коммит `c8150f9` (план 2 S1, круг 1,

   коммит шага откатывает закрытую работу соседнего плана. Следствия: существующий
   ключ снимка `stage` (`snapshot.py:417`) для риска теперь отдаёт `hold_risk` вместо

   для подписи — русский эффект («допуск по риску»), ключ `stage` не меняет значений.
2. `step_pipeline/snapshot.py:229-238` — подпись строится только от действия, а заказ
   постановки и заказ карточки шага приходят одним действием `create_step`
   (`step_pipeline/engine/gate.py:1444-1477`). Когда файл постановки есть, страж
   создаёт карточку шага, причина в карточке обзора это честно пишет
   (`snapshot.py:235`: «постановка шага S1 на месте — страж закажет карточку шага»), а

   закрытия N», коммит `33bbc3b`) подпись врёт почти на каждом шаге, то есть главный
   артефакт шага сообщает неверное последствие. Ожидается: при найденной постановке —
   «Тик: шаг S1» (постановка D2/D9), при отсутствующей — «Тик: заказ постановки S1».
3. `step_pipeline/snapshot.py:292-317` — `plan_totals` запускает движок
   (`next_step.py --plan N`) на каждое соседнее ведомое план; сборка снимка подорожала
   с трёх запусков до четырёх (мой замер выше), при нескольких ведомых планах — больше.
   Постановка §4 запрещает ЛЮБОЙ новый запуск движка в сборке снимка: шаг 3-S1 закрыт
   с критерием «не больше 20 запусков движка в минуту», и §7 п.1 постановки называет
   это стоп-сигналом. Дороже: `ui_server.py:446` сбрасывает кэш снимка после каждого
   действия панели, поэтому четвёртый запуск оплачивается и после каждого нажатия
   кнопки, а не только на старте. Ожидается: число шагов по файлу плана (постановка
   §5.1, `_steps_total`), движок не запускается.
