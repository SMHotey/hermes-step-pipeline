# 6. Оптимизация процессов конвейера

Конституция: docs/CONSTITUTION.md

Цель: конвейер тратит меньше ручной работы и меньше токенов на тот же результат — за счёт
устранения дрейфа движка, подготовленной декомпозиции `gate.py` и метрик цикла, снятых по
замерам, а не назначенных.

## Контекст

Версия плагина 0.25.0, все пять прежних планов закрыты, `gate.py` — 4911 строк. Дальше
расти в одном файле нельзя, но и резать его прямо сейчас нельзя: движок копируется в
проекты по жёсткому кортежу `ENGINE_FILES` (13 имён), поэтому новые модули до проекта не
доезжают, а маркер `ENGINE.sha256` после переноса строк не сойдётся ни у одной живой
установки. Этот порядок зафиксирован в `docs/CONTEXT.md` §9 — план его соблюдает, а не
переизобретает.

Два факта, снятые 12.11.2026 на живой установке:

- `hermes pipeline doctor` на проекте `hermes-step-pipeline` после `setup --upgrade`
  пишет «копия расходится с плагином при равной версии (registry.py, scout_report.py)»,
  хотя содержимое файлов идентично. Причина: `setup_flow.copy_engine` сравнивает файлы
  через `read_text()` (в текстовом режиме CRLF схлопывается в LF), считает их равными и не
  перекопирует, а хеш целостности считается по байтам. То есть копия с CRLF-концами
  навсегда остаётся «расходящейся», и настоящий дрейф в ней уже не отличить от шума.
- Инцидент на потребителе: карточка роли падала с `exit 78` из-за `403` провайдера модели,
  страж восемь тиков подряд писал одну и ту же причину остановки. Причина в тексте была, но
  не отличалась от содержательного блока задачи — владельцу пришлось разбираться вручную.

## Разведка

Артефакт разведки не создавался: `docs/research/6-prior-art.md` отсутствует — разведка по
этому плану не заказывалась.

Кандидатов вне самого репозитория нет: все задачи внутренние — раскладка собственного
движка, тексты стопа, пересчёт весов по собственным замерам. Внешние библиотеки запрещены
инвариантом репозитория (только stdlib и Hermes), поэтому заимствовать нечего.

Лицензии не затрагиваются: чужого кода и практик план не берёт.

Решение: go — делаем своими силами, без разведки готовых решений.

## Допущения

1. Порядок S1 → S2 → S3 обязателен: без копирования «по `*.py`» декомпозиция `gate.py`
   ломает живые установки (ImportError в cron и рассыпавшийся маркер целостности).
2. Разведка готовых решений не проводится: задачи внутренние, внешние зависимости
   запрещены инвариантом репозитория (только stdlib и Hermes).
3. Оценки в днях — ориентир для планирования, а не обязательство.
4. Цифры в плане (4911 строк, 0.25.0, 13 имён в `ENGINE_FILES`) — состояние на 12.11.2026;
   если к началу шага они устарели, шаг фиксирует новые в отчёте, а не подгоняет план.

## Шаги

### S1. Копия движка сравнивается байтами: CRLF-дрейф перестаёт быть «расхождением» (0.5 дн)

- Цель: `doctor` перестаёт ругаться на несуществующее расхождение, а реальный дрейф
  по-прежнему виден и лечится обычным `setup --upgrade`.
- Файл: `step_pipeline/setup_flow.py`, `tests/test_setup_flow.py`, `CHANGELOG.md`
- Тесты/гейты: `python -m pytest tests/test_setup_flow.py -q` → все зелёные, включая новые
- Что сделать: в `copy_engine` сравнивать `read_bytes()` вместо `read_text()`; тест:
  копия с CRLF-концами при равном содержимом перекопируется, после чего `ENGINE.sha256`
  сходится; тест-обратный: изменённый файл перекопируется как раньше.
- Готово = `copy_engine` сравнивает байты, оба теста (CRLF-дрейф и изменённое содержимое)
  зелёные, на проекте `hermes-step-pipeline` после `setup --upgrade` `doctor` не содержит
  строки «копия расходится при равной версии».

### S2. Движок копируется по `*.py`, а не по кортежу `ENGINE_FILES` (1 дн)

- Цель: новый модуль движка доезжает до проекта без правки кортежа в коде плагина.
- Файл: `step_pipeline/setup_flow.py`, `step_pipeline/engine/` (состав), `tests/test_setup_flow.py`,
  `CHANGELOG.md`
- Тесты/гейты: `python -m pytest tests/test_setup_flow.py tests/engine -q` → все зелёные
- Что сделать: копирование и подсчёт `ENGINE.sha256` идут по фактическим `*.py` каталога
  `engine/`; `__pycache__` и посторонние файлы игнорируются; удалённые из плагина модули
  удаляются из проекта при `--upgrade`; кортеж `ENGINE_FILES` удаляется, чтобы не осталось
  второго источника истины.
- Готово = временный каталог с лишним модулем движка после `setup --upgrade` содержит этот
  модуль в `.pipeline/`, `ENGINE.sha256` считается по всем `*.py`, тесты зелёные,
  `ENGINE_FILES` в коде не осталось (`grep -rn ENGINE_FILES step_pipeline/` — пусто).

### S3. Декомпозиция `gate.py` на модули (3 дн)

- Цель: `gate.py` перестаёт быть файлом на 4911 строк — раскладка движка по модулям без
  изменения поведения стража.
- Файл: `step_pipeline/engine/` (новые модули), `step_pipeline/engine/gate.py`,
  `tests/engine/`, `CHANGELOG.md`, `plugin.yaml`
- Тесты/гейты: `python -m pytest` → 600+ тестов зелёные; `GOLDEN_UPDATE` не используется —
  golden-вердикты обязаны совпасть без перезаписи
- Что сделать: вынести из `gate.py` связные блоки (парсинг плана, карточки, журнал,
  решения стража) в отдельные модули, оставив в `gate.py` оркестрацию `run_gate`;
  публичные имена для движка-копии сохранить; резать по одному модулю за коммит.
- Готово = `gate.py` ≤ 1500 строк, все тесты и golden-вердикты зелёные без перезаписи
  эталонов, минорная версия и запись в `CHANGELOG.md`, `hermes plugins validate step_pipeline`
  проходит.

### S4. Вес этапов в прогрессе — из медиан `history.jsonl`, а не из констант (1 дн)

- Цель: прогресс шага считается по фактическим замерам, а не по назначенным весам
  10/55/25/10.
- Файл: `step_pipeline/progress.py`, `step_pipeline/stats.py`, `tests/test_progress.py`,
  `CHANGELOG.md`
- Тесты/гейты: `python -m pytest tests/test_progress.py -q` → все зелёные, включая новые
- Что сделать: считать медианы длительности этапов по закрытым шагам из `history.jsonl`;
  при накоплении достаточного числа замеров брать веса из медиан, при нехватке — падать на
  текущие константы (порог и правило выбора — в тесте); вывод в `status` поясняет, откуда
  веса.
- Готово = на данных из `history.jsonl` веса этапов пересчитываются по медианам, поведение
  при малой выборке не изменилось, оба случая покрыты тестами, источник весов виден в
  `hermes pipeline status`.

### S5. Причина остановки различает поломку роли и содержательный блок (1 дн)

- Цель: владелец по тексту остановки сразу понимает, что делать: чинить роль/провайдера или
  разбирать задачу.
- Файл: `step_pipeline/engine/gate.py` (тексты стопа), `step_pipeline/panel_pause.py`,
  `tests/engine/test_gate_incidents.py`, `CHANGELOG.md`
- Тесты/гейты: `python -m pytest tests/engine/test_gate_incidents.py -q` → все зелёные
- Что сделать: при блокировке карточки различать классы причин — провайдер/модель
  (`exit 78`, `HTTP 401/403`, «provider rejected»), таймаут роли, содержательный блок
  (агент сам попросил решения); в стоп-флаге и в панели выводить класс, готовую команду
  проверки и что именно чинить; повторяющиеся одинаковые причины сводить в одну строку со
  счётчиком вместо восьми копий.
- Готово = три класса причин различаются тестами, в стоп-флаге виден класс и команда,
  одинаковые причины не дублируются, тексты на русском.
