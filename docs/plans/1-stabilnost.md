# 1. Стабилизация конвейера шагов

Цель: закрыть все дефекты P1–P3 из разбора, сделать движок устойчивым к падению и
параллельному запуску, а формат плана — проверяемым до запуска.

## Контекст

Отправная точка: версия 0.1.0, тег v0.1.0 на ff14c10, 96 тестов зелёные (48 плагина +
48 движка), сборка ~50 с. Проверено на Hermes 0.21.5: флаги kanban create
(--idempotency-key, --workspace, --max-runtime), cron create (--no-agent, --script,
--workdir, --deliver local) и profile create (--clone-from) соответствуют тому, что
вызывает плагин; cron в режиме --no-agent подгружает .env профиля (cron/scheduler.py:1489),
то есть уведомления из тика работают.

Найденные дефекты и их точные адреса (чтобы не искать заново):

- gate.py:464 — в теле карточки ревью двойной бэкслеш перед бэктиком: COMMIT_RE такую
  строку не разбирает, проверено. Следствие: APPROVE без ссылки на коммит проходит
  мимо проверки существования коммита (gate.py:885).
- gate.py:283-296 — «чужие правки» только печатаются, а git commit без списка путей
  коммитит всё, что уже лежит в индексе.
- gate.py:126-137, 238-271 — состояние и журнал пишутся прямым write_text, блокировки
  тика нет: cron, кнопка «Тик» в панели и инструмент pipeline_run могут идти одновременно.
- gate.py:1013 — main() без обработчика: любое исключение даёт трейсбек, инцидентный
  стоп не ставится, уведомления нет, конвейер просто перестаёт идти.
- next_step.py:184 и registry.py:116 — две собственные копии регулярки шага,
  cfg.step_id_regex при разборе плана не применяется.
- gate.py:198 и registry.py:97 — два разных определения «журнала» (с проверкой строк-шагов
  и без).
- ui_control.py:53 — tasklist читается как text=True без encoding: на русской консоли
  UnicodeDecodeError в потоке читателя (воспроизведено под -W error).
- ui_server.py:239-271 — POST не проверяет Content-Type и Origin: чужая страница в
  браузере может дёрнуть stop/tick/save_config без preflight.
- cli.py:209-282 — doctor не проверяет входной формат: неверный план даёт не ошибку,
  а вечный idle без уведомления.
- plugin.yaml:18-34 — config_schema (project_root, ui_port) не читается кодом.
- Покрытие: агрегат 52%, gate.py 22% — артефакт подпроцессных e2e; step_card.py и
  tick.py 0%, ui_control.py 47%.

Порядок работ: сначала P1 (S1–S4), затем P2 (S5–S9), затем инфраструктура и гигиена
(S10–S14). Планы 2 и 3 опираются на этот: линтер плана (S8) и история тиков (план 2, S3)
нужны панели.

Грабли, которые этот план обязан не наступить:

- Список файлов движка продублирован: setup_flow.py:27 (ENGINE_FILES) и
  tests/engine/engine_kit.py:21. Новый модуль движка надо добавлять в оба места,
  иначе setup --upgrade не привезёт файл, а тесты будут зелёными на старом наборе.
- Любое изменение поведения движка — минимум минор версии: plugin.yaml, CHANGELOG.md,
  маркер .pipeline/VERSION в проектах обновляется через setup --upgrade.
- hermes в PATH не гарантирован: тесты подменяют proj.run_hermes и кладут поддельный
  бинарник в PATH, настоящий вызывать нельзя.
- Покрытие 52% — цифра лукавая: e2e-тесты гоняют gate.py подпроцессом, coverage их не
  видит, поэтому 22% у самого важного модуля означают «не измерено», а не «не проверено».
- Проверять парсинг планов надо движком, а не глазами: PIPELINE_REPO и
  PIPELINE_ASSUME_DEFAULTS=1 дают разбор любого проекта без установки конвейера.

- Тесты/гейты: `python -m pytest tests/engine/test_review_card.py -q` → 3 passed
- Что сделать: в строке шаблона тела карточки (gate.py:464) убрать двойное
  экранирование обратной кавычки; карточка должна показывать ровно одну пару бэктиков
  вокруг образца sha; затем прогнать COMMIT_RE по строке, взятой прямо из карточки,
  без ручной правки.
- Готово = тест «строка из карточки ревью разбирается verdict_of в тот же sha» зелёный
  и краснеет на коде до правки; при APPROVE в журнал попадает sha, а не прочерк.

### S2. Безопасный коммит: только свои файлы (0.5 дн)

- Файл: `step_pipeline/engine/gate.py`, `tests/engine/test_commit.py`
- Тесты/гейты: `python -m pytest tests/engine/test_commit.py -q` → 5 passed

  защиту; когда по своим файлам изменений нет — возвращать успех с текстом «нечего
  коммитить» вместо падения; push делать только при настроенном upstream, иначе
  понятная причина в detail.
- Готово = посторонний файл, добавленный в индекс до тика, остаётся вне коммита стража;
