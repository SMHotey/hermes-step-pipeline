## Допущения

1. Замер — не отчёт для человека, а данные: jsonl в `.pipeline/state`, читают страж и
   панель. Отчёт для владельца собирается из тех же строк, второго источника нет.
2. Источник чисел — `agent.log` профиля воркера: только там есть вызовы модели и
   длительности инструментов изнутри процесса. Формат лога чужой (Hermes), поэтому парсер
   закрывается тестом-фикстурой, а не «как получится».
3. Защита от цикла не отменяет лимит: шаг по-прежнему убивается по времени. Меняется
   реакция на убийство — повтор требует изменения условий.
4. Один автоматический перезапуск после убийства по лимиту допустим с эскалацией:
   лимит ×1,5 и метод работы, записанный в карточку. Второй подряд — стоп владельцу.
5. Правило «артефакт первым» (S6) — предупреждение в карточку и уведомление, а не
   убийство шага: судить о работе по отсутствию файла движок не вправе.
6. `step_pipeline/engine/gate.py` трогают S1, S3 и S4: один расчёт чисел, одно решение о
   повторном запуске, один стоп. Порядок шагов = порядок ветвей: сначала числа, потом
   сохранение прогресса, потом запрет цикла.
7. Новых зависимостей нет: `json`, `re`, `statistics`, `time` из stdlib.
8. Профиль роли разводим по проекту только по признаку, а не «для чистоты скиллов»: скиллы
   проекта лежат в его дереве (`.hermes/skills`) и в профиле не смешиваются, карточка несёт
   рабочее дерево проекта. Разводим, если выполнено хотя бы одно: (а) нужна другая модель,
   провайдер или набор инструментов; (б) в память профиля попали факты одного проекта и
   мешают другому; (в) роль стала бутылочным горлышком — шаги ждут свободного профиля
   больше 20 % времени (считается по S1, время шага по фазам); (г) у проекта своя методика
   роли, конфликтующая с общей. Общими остаются роли «про реестр»: `pipeline-keeper`,
   `pipeline-orchestrator`, `pipeline-observer`; драйвер и постановщик — по проекту.
   Следствие для S8: наблюдатель — один профиль `observer` на все проекты, не по копии на
   каждый; прецеденты расхождения копий (тик-скрипт, молча возвращавший 0; две копии
   движка при равном `VERSION`) — прямой аргумент против размножения профилей без признака.
