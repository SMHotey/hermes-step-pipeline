## Разведка

Артефакт: **`docs/research/7-prior-art.md`** (разведка 12.11.2026: как индустрия добивается
сходимости итеративного ревью — линтеры, «находки как трекер», freeze scope; кандидатов 9, решение

внешних библиотек и новых зависимостей план не добавляет.

## Допущения

1. Формат отчёта ревью **не меняется** (первая строка `plan_sha256:`, вердикт, находки) — реестр
   живёт отдельным файлом `docs/reviews/plan-<N>-findings.md`, иначе ломаются существующие отчёты и панель.
2. Реестр — производная сущность: если файла нет, движок работает по-старому (легаси-проекты не
   ломаются), реестр создаётся при первом ревью плана по новой версии.
3. Класс «исполнимость команд гейтов» перестаёт блокировать ревью плана, но остаётся находкой
   класса «проверить при исполнении»: она попадает в карточку шага, а не в вердикт плана.
4. Лимит расширения плана правкой — числовой и настраиваемый (`max_plan_growth`, дефолт 10% и
   не больше 400 символов на одну находку); привышение — стоп-сигнал карточки правок, а не тихое усечение.
5. Старые тесты движка остаются зелёными; новые тесты — на каждый шаг (happy path, границы, интеграция).
6. Оценки — рабочие дни профиля `pipeline`, суммарно 8.

### S1. Реестр находок плана: файл, схема, заполнение (1.5 дн) `pipeline`

- Цель: у ревью плана появляется накопительный реестр находок с идентификаторами и статусами, по
  которому можно доказать исчерпание замечаний, а не полагаться на «в этот раз ничего не нашли».
- Файл: `step_pipeline/engine/gate.py`, `step_pipeline/engine/config.py`, `tests/test_plan_findings.py` (новый)
- Работа: путь реестра строится **из того же источника, что и отчёт ревью** — cfg.reviews_dir
  (ключ paths.reviews, шаг правит `step_pipeline/engine/config.py`), рядом с review_path из
  `approval`; второго сборщика пути не заводим (gate.plan_review_path предупреждает: второй сборщик
  молча разойдётся с первым).
  Функции `load_findings()`, `write_findings()`, `add_findings()`: таблица
  `| ID | Шаг | Класс | Находка | Что сделать | Статус |`; ID — `F<N>` сквозной по плану; статусы
  `открыто`, `закрыто`, `не блокирует`.
  Словарь классов закрытый и определён только здесь: `замысел`, `двусмысленность`, `формат-стража`,
  `гейт-исполнение`, `стиль`.
  **Единственное правило блокирования, общее для S2 и S3:** блокирует только статус — находка со
  статусом `открыто` блокирует вердикт, `закрыто` и `не блокирует` — нет. Класс ничего не блокирует:
  он выбирает лишь, в какую карточку уходит находка (S3). Статус ставит ведущий реестра,
  переопределений «по классу» в S2 и S3 нет.
  При создании карточки ревью плана тело получает реестр целиком и требование: закрыть/подтвердить
  открытые ID, новые добавить строками. Отчёт ревью остаётся как есть, реестр — дополнительный
  файл, который ведёт ревьюер.
- Тесты/гейты: `python -m pytest tests/test_plan_findings.py -q` → 8 passed (создание, добавление,
  закрытие, дубль ID, битый файл, отсутствие файла, юникод, сохранение порядка);
  `python -m pytest tests/ -q -k "plan_review or findings"` → 0 failed.
- Стоп-сигнал: реестр требует правки формата отчёта (первая строка `plan_sha256:`) → остановиться и
  вынести вопрос владельцу, формат отчёта не трогать.
- Готово = реестр создаётся и обновляется, тесты зелёные, формат отчёта не изменён.

### S2. Вердикт по реестру и заморозка классов находок (1.5 дн) `pipeline`

- Цель: `APPROVE` наступает, когда в реестре нет открытых блокирующих находок, а после первого
  круга новые находки допускаются только как регрессия от последней правки.
- Файл: `step_pipeline/engine/gate.py`, `step_pipeline/roles/pipeline-plan-reviewer/SKILL.md`, `tests/test_plan_review_verdict.py` (новый)

  вердикт иной (расхождение логируется и попадает в комментарий карточки); в теле карточки ревью круга ≥ 2 — требование
  «новые находки только по строкам, изменённым последней правкой»; в роли ревьюера — правило
  «открытые ID закрываются фактом, закрытые не переоткрываются».
- Тесты/гейты: `python -m pytest tests/test_plan_review_verdict.py -q` → 6 passed (нет реестра —

- Готово = вердикт плана считается по реестру, тесты зелёные.
